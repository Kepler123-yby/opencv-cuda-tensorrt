# 1.2 用 CMake 自动检测推理后端

> **对应 SLT**：我能编写 CMake 配置自动检测推理后端与 CUDA 能力，并编译进同一个库。
> **课时类型**：Developer Documentation
> **前置**：1.1 已有一个带 CUDA 的 OpenCV

---

## 为什么让 CMake 去「找」

一个部署库通常要同时支持多种后端：CPU 版 OpenCV、带 CUDA 的 OpenCV、TensorRT、甚至 OpenVINO。不同机器上装的东西不一样，你不可能为每台机器手改代码。

更省心的做法是：**让 CMake 去检测哪些后端可用，把结果变成编译期宏**，源码里用 `#if` 分开编译。这样同一份代码在「只有 OpenCV」和「有 TensorRT」的机器上都能编过，运行时再用配置选后端，**无需重新编译**。

本节要做三件事：检测后端、按检测结果链接库、把结果传成宏。

---

## 后端检测的三段式

### 1. OpenCV 与它的 CUDA 模块

`find_package(OpenCV)` 会提供一个 `OpenCV_LIBS`。判断有没有 CUDA 模块，最可靠的办法是看它导出的 **CMake target**：

```cmake
find_package(OpenCV REQUIRED COMPONENTS core imgproc videoio)

set(HAVE_OPENCV_CUDA OFF)
if(TARGET opencv_cudawarping AND TARGET opencv_cudaarithm)
  set(HAVE_OPENCV_CUDA ON)
endif()
```

只要 `find_package` 命中的是带 CUDA 的 OpenCV（见 1.1 的 `OpenCV_DIR`），这些 target 就会出现。

### 2. TensorRT：先正规找，找不到再手动找

TensorRT 的 CMake 包不是所有发行版都提供，所以要有**回退路径**：

```cmake
find_package(TensorRT QUIET)

if(TensorRT_FOUND)
  set(HAVE_TENSORRT ON)
else()
  find_path(TENSORRT_INCLUDE_DIR NvInfer.h
            HINTS ${TENSORRT_ROOT} /usr/include /usr/local/include
            PATH_SUFFIXES include)
  find_library(TENSORRT_NVINFER NAMES nvinfer
               HINTS ${TENSORRT_ROOT} PATH_SUFFIXES lib lib/x64)
  find_library(TENSORRT_NVONNXPARSER NAMES nvonnxparser
               HINTS ${TENSORRT_ROOT} PATH_SUFFIXES lib lib/x64)

  if(TENSORRT_INCLUDE_DIR AND TENSORRT_NVINFER AND TENSORRT_NVONNXPARSER)
    set(HAVE_TENSORRT ON)
    set(TensorRT_INCLUDE_DIRS ${TENSORRT_INCLUDE_DIR})
    set(TensorRT_LIBRARIES ${TENSORRT_NVINFER} ${TENSORRT_NVONNXPARSER})
  else()
    set(HAVE_TENSORRT OFF)
  endif()
endif()
```

把解压版的 TensorRT 路径通过 `-DTENSORRT_ROOT=~/tensorrt/TensorRT-10.10.0.31` 传进来，`find_path`/`find_library` 就能命中。

### 3. 只有真的找不到任何后端，才报错

```cmake
if(NOT HAVE_OPENCV_CUDA AND NOT HAVE_TENSORRT)
  message(FATAL_ERROR "至少需要一个推理后端（OpenCV CUDA 或 TensorRT）")
endif()
```

## 把检测结果变成宏

检测出来还要用得上。用 `target_compile_definitions` 把结果传给源码：

```cmake
add_library(nndeploy_lib
  src/preprocess/network_preprocess.cpp
  src/postprocess/network_postprocess.cpp
)

target_include_directories(nndeploy_lib PUBLIC include)
target_link_libraries(nndeploy_lib PRIVATE ${OpenCV_LIBS})

if(HAVE_TENSORRT)
  target_include_directories(nndeploy_lib PRIVATE ${TensorRT_INCLUDE_DIRS})
  target_link_libraries(nndeploy_lib PRIVATE ${TensorRT_LIBRARIES})
  target_compile_definitions(nndeploy_lib PRIVATE NNDEPLOYMENT_WITH_TENSORRT=1)
endif()

if(HAVE_OPENCV_CUDA)
  enable_language(CUDA)   # 有 .cu 文件时才需要
  target_compile_definitions(nndeploy_lib PRIVATE NNDEPLOYMENT_WITH_OPENCV_CUDA=1)
endif()
```

源码里这样用：

```cpp
#ifndef NNDEPLOYMENT_WITH_TENSORRT
#define NNDEPLOYMENT_WITH_TENSORRT 0
#endif

#if NNDEPLOYMENT_WITH_TENSORRT
// 只有 TensorRT 可用时才编译这段
#endif
```

**默认值很关键**：宏在没有定义时要能被当成 `0`，否则 `#if NNDEPLOYMENT_WITH_TENSORRT` 会直接报「未定义标识符」。所以每个宏都要在源码顶部兜底。

## 打印检测结果

配置阶段的可见输出，是排查「为什么后端没生效」的第一手线索：

```cmake
message(STATUS "OpenCV 版本:   ${OpenCV_VERSION}")
message(STATUS "OpenCV CUDA:   ${HAVE_OPENCV_CUDA}")
message(STATUS "TensorRT:      ${HAVE_TENSORRT}")
```

## 验证

配置时传入 TensorRT 路径，观察输出：

```bash
cmake -S . -B build \
  -DOpenCV_DIR=$HOME/opt/opencv-cuda/lib/cmake/opencv4 \
  -DTENSORRT_ROOT=$HOME/tensorrt/TensorRT-10.10.0.31
```

预期能看到：

```
-- OpenCV 版本:   4.13.0
-- OpenCV CUDA:   ON
-- TensorRT:      ON
```

三项都是 `ON` 才算成功。**注意**：配置输出里如果没有这几行，说明 `message(STATUS ...)` 没被走到，检查变量名有没有拼错。

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `OpenCV CUDA: OFF` | 找到的是 CPU 版 OpenCV | 传 `-DOpenCV_DIR=.../opencv-cuda/lib/cmake/opencv4` |
| `TensorRT: OFF` | 路径不对或库名不符 | 检查 `TENSORRT_ROOT` 下的 `include/NvInfer.h` 与 `lib/libnvinfer.so` |
| 链接时报 `undefined reference` | 检出了头文件但没链库 | 确认 `target_link_libraries` 里带上了 TensorRT 库 |
| 源码 `#if` 报宏未定义 | 没写默认值 | 在源码顶部 `#define ... 0` 兜底 |
| `.cu` 文件报错 | 没启用 CUDA 语言 | 在 `if(HAVE_OPENCV_CUDA)` 里 `enable_language(CUDA)` |
