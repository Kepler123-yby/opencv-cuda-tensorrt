# 1.1 从源码编译启用 CUDA 的 OpenCV

> **对应 SLT**：我能从源码编译启用 CUDA 与 cuDNN 的 OpenCV，并安装到独立前缀与系统 CPU 版共存。
> **课时类型**：How To Guide
> **前置**：NVIDIA GPU + 已装驱动；会用 CMake 编译 C++ 项目

---

## 为什么必须自己编译

Ubuntu 的 `libopencv-dev` 是**不带 CUDA** 的。它没有 `cv::cuda` 命名空间，也没有 `cudawarping`、`cudaimgproc` 这些模块。想用 `GpuMat`，只能自己从源码编译一个启用 CUDA 的版本。

麻烦在于：系统里可能已经有 CPU 版 OpenCV（很多工具依赖它）。如果你把 CUDA 版覆盖着装到 `/usr/local`，迟早会把系统里的东西搞乱。稳妥做法是**独立前缀安装**：新版本装到自己的目录，需要时显式告诉编译器用哪一个。

本节的产物是：一个带 CUDA 的 OpenCV，位于独立前缀，和系统 CPU 版互不干扰。

---

## 前置检查

先确认 GPU、驱动、CUDA 都在位：

```bash
nvidia-smi                 # 能看到 GPU 型号与驱动版本
nvcc --version             # 能看到 CUDA 版本
```

`nvidia-smi` 显示的是**驱动**支持的 CUDA 版本，`nvcc` 显示的是**工具链**版本，两者要兼容。把 `nvcc` 的输出记下来，后面配 OpenCV 要用。

查一下显卡算力（Compute Capability），这是 `CUDA_ARCH_BIN` 的取值依据：

| 显卡代次 | 架构 | 算力 |
|---|---|---|
| RTX 30 系 | Ampere | 8.6 |
| RTX 40 系 | Ada | 8.9 |
| 数据中心 A100 | Ampere | 8.0 |

不确定就用 `nvidia-smi --query-gpu=compute_cap --format=csv` 直接问。

装编译依赖与编解码库：

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build git pkg-config
sudo apt install -y libavcodec-dev libavformat-dev libavutil-dev \
                    libswscale-dev libavdevice-dev libjpeg-dev libpng-dev libtiff-dev
```

---

## 步骤 1：获取 OpenCV 与 opencv_contrib 源码

`opencv_contrib` 里放了额外模块，某些 CUDA 能力依赖它，一起拉下来：

```bash
mkdir -p ~/opencv_build && cd ~/opencv_build

git clone --depth 1 --branch 4.x https://github.com/opencv/opencv.git
git clone --depth 1 --branch 4.x https://github.com/opencv/opencv_contrib.git
```

> `--branch 4.x` 跟随 4.x 主线。生产环境建议固定到某个 `4.x.y` 标签，版本可复现。

---

## 步骤 2：准备 cuDNN

只有在你要用 **OpenCV DNN 的 CUDA 后端**（`cv::dnn` + `DNN_BACKEND_CUDA`）时才需要 cuDNN。如果你只用 `cv::cuda` 的算子（resize、cvtColor 等），可以跳过这一步，并把后面配置里的 cuDNN 开关关掉。

cuDNN 与 CUDA 主版本要对应：CUDA 11 用 `nvidia-cudnn-cu11`，CUDA 12 用 `nvidia-cudnn-cu12`。没有 NVIDIA 账号时，可以直接从 PyPI 下载 wheel 解包：

```bash
mkdir -p ~/opt/cudnn_dl && cd ~/opt/cudnn_dl
python3 -m pip download --no-deps nvidia-cudnn-cu11 -d .

mkdir -p ~/opt/cudnn && cd ~/opt/cudnn
python3 -m zipfile -e ~/opt/cudnn_dl/nvidia_cudnn_cu11-*.whl .
cd nvidia/cudnn/lib && ln -sf libcudnn.so.* libcudnn.so && cd -
# 结果：~/opt/cudnn/nvidia/cudnn/{include,lib}
```

**验证**：确认头文件与库都在。

```bash
ls ~/opt/cudnn/nvidia/cudnn/include/cudnn.h
ls ~/opt/cudnn/nvidia/cudnn/lib/libcudnn.so
```

两条命令都应输出文件路径。若第一条报「没有那个文件」，说明 wheel 版本或解包路径不对。

---

## 步骤 3：配置 CMake

把关键开关指向独立前缀与你的 GPU 算力。下面用 RTX 30 系（算力 8.6）举例，按需替换。

```bash
cd ~/opencv_build

cmake -S opencv -B build_cuda -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/opt/opencv-cuda" \
  -DOPENCV_EXTRA_MODULES_PATH="$PWD/opencv_contrib/modules" \
  -DWITH_CUDA=ON \
  -DCUDA_ARCH_BIN=8.6 \
  -DCUDA_ARCH_PTX= \
  -DCUDA_TOOLKIT_ROOT_DIR=/usr/local/cuda \
  -DWITH_CUDNN=ON \
  -DOPENCV_DNN_CUDA=ON \
  -DCUDNN_INCLUDE_DIR="$HOME/opt/cudnn/nvidia/cudnn/include" \
  -DCUDNN_LIBRARY="$HOME/opt/cudnn/nvidia/cudnn/lib/libcudnn.so" \
  -DWITH_NVCUVID=OFF \
  -DBUILD_opencv_cudacodec=OFF \
  -DOPENCV_GENERATE_PKGCONFIG=ON \
  -DBUILD_TESTS=OFF -DBUILD_PERF_TESTS=OFF -DBUILD_EXAMPLES=OFF \
  -DBUILD_JAVA=OFF -DBUILD_DOCS=OFF
```

几个开关的含义，值得记住：

| 开关 | 作用 |
|---|---|
| `CMAKE_INSTALL_PREFIX` | 独立前缀，**不覆盖**系统 OpenCV 的关键 |
| `WITH_CUDA=ON` | 启用 `cv::cuda` 模块 |
| `CUDA_ARCH_BIN` | 只编译你的 GPU 算力，缩短编译时间、减小体积 |
| `WITH_CUDNN` + `OPENCV_DNN_CUDA` | 启用 DNN 的 CUDA 后端；不用可都关掉 |
| `WITH_NVCUVID=OFF` | 不装 NVIDIA Video Codec SDK 时关掉，否则配置失败 |
| `OPENCV_GENERATE_PKGCONFIG=ON` | 生成 `.pc` 文件，方便 `pkg-config` 使用 |

**验证**：配置结束后，回看输出里的 CUDA 段，应出现：

```
--   NVIDIA CUDA:                   YES (ver 11.8, CUFFT CUBLAS)
--   cuDNN:                         YES (ver 9.x.x)
```

若 `NVIDIA CUDA` 显示 `NO`，多半是 `CUDA_TOOLKIT_ROOT_DIR` 指错或 `nvcc` 不在 `PATH`。

---

## 步骤 4：编译与安装

```bash
cmake --build build_cuda -j"$(nproc)"
sudo cmake --install build_cuda
```

编译时间较长，可以在配置时加 `-DCMAKE_C_COMPILER_LAUNCHER=ccache -DCMAKE_CXX_COMPILER_LAUNCHER=ccache` 用 ccache 加速后续重建。

安装后刷新动态库缓存：

```bash
sudo ldconfig
```

---

## 步骤 5：写一个环境脚本

独立前缀的代价是：用它之前要显式设置几组环境变量。写成一个脚本，每次 `source` 一下即可。

```bash
cat > ~/opt/opencv-cuda/opencv_cuda_env.sh <<'EOF'
export OpenCV_DIR="$HOME/opt/opencv-cuda/lib/cmake/opencv4"
export PKG_CONFIG_PATH="$HOME/opt/opencv-cuda/lib/pkgconfig:$PKG_CONFIG_PATH"
export LD_LIBRARY_PATH="$HOME/opt/opencv-cuda/lib:$HOME/opt/cudnn/nvidia/cudnn/lib:$LD_LIBRARY_PATH"
export PYTHONPATH="$HOME/opt/opencv-cuda/lib/python3/dist-packages:$PYTHONPATH"
export PATH="$HOME/opt/opencv-cuda/bin:$PATH"
EOF
```

用法：

```bash
source ~/opt/opencv-cuda/opencv_cuda_env.sh
```

---

## 验证

```bash
source ~/opt/opencv-cuda/opencv_cuda_env.sh
pkg-config --modversion opencv4
```

应输出版本号（例如 `4.13.0`）。再确认 CUDA 能力：

```bash
opencv_version --verbose 2>/dev/null | grep -i cuda
```

应看到 `NVIDIA CUDA: YES`。Python 侧：

```bash
python3 -c "import cv2; print(cv2.__version__, cv2.cuda.getCudaEnabledDeviceCount())"
```

预期打印 `版本号 1`（设备数为 1）。**若打印 `0`，是本节最常见的失败，见下。**

---

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 配置时 `NVIDIA CUDA: NO` | 找不到 `nvcc` 或 Toolkit 路径 | 设 `CUDA_TOOLKIT_ROOT_DIR`，确认 `nvcc` 在 `PATH` |
| `getCudaEnabledDeviceCount()==0` | 没 `source` 环境脚本；或运行时找不到 CUDA 版 `.so` | `source` 后确认 `LD_LIBRARY_PATH` 含独立前缀 |
| 运行时报找不到 `libopencv_core.so.*` | `LD_LIBRARY_PATH` 缺失 | 再 `source` 脚本 |
| DNN 报找不到 `libcudnn.so` | cuDNN 库目录不在 `LD_LIBRARY_PATH` | 把 cuDNN `lib` 目录加进去（脚本已含） |
| Python `import cv2` 仍加载系统版 | `PYTHONPATH` 未生效 | 打印 `cv2.__file__` 确认指向独立前缀 |
| 同一进程同时链接两个 OpenCV | 系统版与独立版 ABO 冲突 | **不要混链**；一个进程只用一个版本 |

> **ABI 提醒**：独立前缀与系统版可能版本号相同、`.so` 同名。同一进程里绝不要同时加载两套，否则会产生难以定位的崩溃。用 `LD_LIBRARY_PATH` 明确指定用哪套。
