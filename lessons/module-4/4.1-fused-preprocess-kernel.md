# 4.1 融合预处理 kernel：直接写入 TensorRT 输入显存

> **对应 SLT**：我能编写融合 letterbox、通道转换与归一化的 CUDA kernel，直接写入设备输入缓冲区。
> **课时类型**：Developer Documentation
> **前置**：2.1 GpuMat、2.2 letterbox、3.2 TensorRT 缓冲区
> **范围**：batch=1、BGR uint8 输入、RGB float32 NCHW 输出；代码片段由 nvcc 编译为 `.cu`，不是完整推理程序。

## 1. 先固定输入契约，再谈融合

典型 CPU 路径是：缩放 → 补边 → BGR 转 RGB → /255 → HWC 转 NCHW → 上传模型输入。融合 kernel 把这些步骤直接写入 TensorRT 的输入显存：

```text
cv::Mat --一次 H2D--> GpuMat --融合 kernel--> d_input --enqueueV3--> d_output
```

减少的是中间图像的落地、格式转换的临时缓冲和重复传输，**不是消除原图的第一次上传**。

本例的模型输入必须是 `kFLOAT`、线性格式 `[1,3,H,W]`。TensorRT 内部使用 FP16 tactic，并不意味着模型 IO 一定是 FP16；先查询 `getTensorDataType(name)` 和 `getTensorFormat(name)`。如果输入是 HALF、INT8 或打包格式，不能照抄 `float*` 写入方式。

padding 值也是模型契约。本例沿用 124；很多 YOLO 实现用 114，必须与训练/导出预处理一致。减均值、除标准差的模型也不能只做 /255。

## 2. letterbox 的舍入与不对称 padding

先计算缩放后整数尺寸，再把剩余像素分到两侧。剩余宽度为奇数时，右侧会比左侧多一像素，不要假设左右完全对称。

```cpp
#include <algorithm>
#include <cmath>
#include <stdexcept>

struct Letterbox {
    int new_w, new_h;
    int pad_x, pad_y;  // 左侧、上侧
};

Letterbox makeLetterbox(int src_w, int src_h, int target_w, int target_h)
{
    if (src_w <= 0 || src_h <= 0 || target_w <= 0 || target_h <= 0)
        throw std::invalid_argument("图像尺寸必须为正");
    double s = std::min(double(target_w) / src_w, double(target_h) / src_h);
    int nw = std::clamp(int(std::round(src_w * s)), 1, target_w);
    int nh = std::clamp(int(std::round(src_h * s)), 1, target_h);
    return {nw, nh, (target_w - nw) / 2, (target_h - nh) / 2};
}
```

有效区域是 `[pad_x, pad_x + new_w)`，不是 `[pad_x, target_w - pad_x)`。后者会在奇数 padding 时多处理一列。

像素采样使用半像素坐标：

```text
src_x = (x - pad_x + 0.5) × src_w / new_w - 0.5
src_y = (y - pad_y + 0.5) × src_h / new_h - 0.5
```

不能在整数尺寸舍入后，仍用同一个理想 `scale` 代替两个实际尺寸比。记录 `new_w/new_h/pad_x/pad_y`，每帧随结果保存；后处理按同一几何约定逆变换。

## 3. GpuMat 是带行步长的图像，不是连续 NCHW 张量

`GpuMat::step` 是每行的**字节数**，可能大于 `cols * 3`。ROI 子图也保留原图的步长：

```cpp
const unsigned char* row = src + size_t(y) * src_step;
const unsigned char* pixel = row + x * 3;
```

`step` 用 `size_t` 保存，不缩成 `int`。TensorRT 本例的输入则是连续的三个 float 平面。把 `GpuMat::data` 原样绑定给 TensorRT，既没有改变颜色/类型，也没有改变布局。

## 4. 双线性采样与融合 kernel

```cpp
#include <cuda_runtime.h>
#include <cstddef>
#include <cmath>

__device__ float readChannel(
    const unsigned char* src, size_t step,
    int src_w, int src_h, int x, int y, int channel)
{
    x = max(0, min(x, src_w - 1));
    y = max(0, min(y, src_h - 1));
    return src[size_t(y) * step + size_t(x) * 3 + channel];
}

__device__ float bilinear(
    const unsigned char* src, size_t step,
    int src_w, int src_h, double x, double y, int channel)
{
    int x0 = int(floor(x));
    int y0 = int(floor(y));
    float dx = float(x - x0), dy = float(y - y0);
    float a = readChannel(src, step, src_w, src_h, x0, y0, channel);
    float b = readChannel(src, step, src_w, src_h, x0 + 1, y0, channel);
    float c = readChannel(src, step, src_w, src_h, x0, y0 + 1, channel);
    float d = readChannel(src, step, src_w, src_h, x0 + 1, y0 + 1, channel);
    return (a * (1 - dx) + b * dx) * (1 - dy)
         + (c * (1 - dx) + d * dx) * dy;
}

__global__ void letterboxBgrToRgbNchwKernel(
    const unsigned char* src, size_t src_step,
    int src_w, int src_h, float* dst,
    int target_w, int target_h,
    int new_w, int new_h, int pad_x, int pad_y,
    float pad_value)
{
    int index = blockIdx.x * blockDim.x + threadIdx.x;
    int total = target_w * target_h;
    if (index >= total) return;
    int x = index % target_w, y = index / target_w;
    float b = pad_value, g = pad_value, r = pad_value;

    bool inside = x >= pad_x && x < pad_x + new_w
               && y >= pad_y && y < pad_y + new_h;
    if (inside) {
        double sx = (double(x - pad_x) + 0.5) * src_w / new_w - 0.5;
        double sy = (double(y - pad_y) + 0.5) * src_h / new_h - 0.5;
        b = bilinear(src, src_step, src_w, src_h, sx, sy, 0);
        g = bilinear(src, src_step, src_w, src_h, sx, sy, 1);
        r = bilinear(src, src_step, src_w, src_h, sx, sy, 2);
    }
    dst[index]             = r / 255.0f;
    dst[total + index]     = g / 255.0f;
    dst[2 * total + index] = b / 255.0f;
}
```

一个线程处理一个目标像素，写三个平面。`readChannel` 在边缘夹紧索引，防止双线性邻点越界。

教学基线使用 double 计算采样坐标，再用 float 做插值，避免较大原图上坐标舍入放大为像素误差。独显的 FP64 吞吐可能较低；后续可改用 float 坐标优化，但必须重新测误差与性能，不能默认数值完全等价。

## 5. 启动、错误检查与 TensorRT 接入

以下函数与上面的 `Letterbox`、kernel 放在同一个 `.cu` 编译单元里：

```cpp
#include <opencv2/core/cuda.hpp>

cudaError_t launchFusedPreprocess(
    const cv::cuda::GpuMat& src, float* d_input,
    int target_w, int target_h, Letterbox lb,
    float pad_value, cudaStream_t stream)
{
    if (src.empty() || src.type() != CV_8UC3 || d_input == nullptr ||
        target_w <= 0 || target_h <= 0 || lb.new_w <= 0 || lb.new_h <= 0 ||
        lb.pad_x < 0 || lb.pad_y < 0 ||
        lb.pad_x + lb.new_w > target_w || lb.pad_y + lb.new_h > target_h)
        return cudaErrorInvalidValue;

    int total = target_w * target_h;  // 本例目标尺寸应使 int 不溢出
    letterboxBgrToRgbNchwKernel<<<(total + 255) / 256, 256, 0, stream>>>(
        src.ptr<unsigned char>(), src.step, src.cols, src.rows, d_input,
        target_w, target_h, lb.new_w, lb.new_h, lb.pad_x, lb.pad_y, pad_value);
    return cudaPeekAtLastError();  // 检查 launch；执行期错误在同步时检查
}
```

调用方保证 `d_input` 至少有 `3 * target_w * target_h * sizeof(float)` 字节。不要因为 engine 内部用了 FP16 就少分配一半。

OpenCV 上传、kernel、TensorRT 必须有顺序依赖。可以把原生 CUDA 流包装给 OpenCV：

```cpp
#include <opencv2/core/cuda_stream_accessor.hpp>

// stream、gpu_bgr、原始 host 图像、d_input 都属于长生命周期请求槽位。
cv::cuda::Stream cv_stream = cv::cuda::StreamAccessor::wrapStream(stream);
gpu_bgr.upload(host_image, cv_stream);
Letterbox lb = makeLetterbox(host_image.cols, host_image.rows, 640, 640);

cudaError_t err = launchFusedPreprocess(gpu_bgr, d_input, 640, 640, lb, 124, stream);
if (err != cudaSuccess) throw std::runtime_error(cudaGetErrorString(err));
if (!context->enqueueV3(stream)) throw std::runtime_error("enqueueV3 失败");
```

这里不在预处理后同步。同一 stream 自动保持顺序；在消费最终结果时同步并检查错误。

**生命周期是正确性的一部分**：入队成功不代表 GPU 已读完。不要在函数返回时销毁局部 `GpuMat`，也不要修改上传源或复用 `d_input`。保留相关资源，直到请求完成事件触发。想稳定重叠 H2D 与计算，使用持久的页锁定上传缓冲；普通 `cv::Mat` 的上传不保证与计算真正重叠。

## 6. 验证与练习

先比较预处理，不跑模型：CPU 生成 RGB NCHW 参考，GPU 输出下载仅用于测试。

- 横图、竖图、原尺寸图、1×1 图都要覆盖。
- 使用通道值不同的彩色图，不要只用灰图。
- 测试一个 ROI，验证 `step` 不是 `width * 3` 时仍正确。
- 用产生奇数 padding 的尺寸（如 641×480 → 640×640）检查多出来的一侧。

本融合路径直接保留 float 插值值；`cv::resize` 到 uint8 后再 `blobFromImage` 会多一次量化，不能要求逐位相同。与一致几何约定的 CPU 参考比较，先记录最大/平均误差，再设经过测试的容差；`2/255` 可作 uint8 中间量化路径的初始观察阈值，不是所有模型的保证。

课程的检查脚本与完整测试流程见 [4.4](4.4-cpu-gpu-parity.md)。

## 7. 排错顺序

| 现象 | 先检查 |
|---|---|
| 输出颜色错 | RGB 平面顺序、模型是否其实需要 BGR |
| 图出现斜纹 | `src_step` 与 ROI |
| 边缘多一列原图 | 奇数 padding 的有效区域判断 |
| 数值整体错 | IO 数据类型、/255、均值与标准差 |
| 偶发错帧 | buffer 复用与 `GpuMat` 生命周期 |
