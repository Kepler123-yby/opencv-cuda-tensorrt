# 4.2 GPU 并行解码：候选筛选与 atomicAdd 压缩

> **对应 SLT**：我能编写并行解码检测候选的 CUDA kernel，并用原子操作压缩结果。
> **课时类型**：Developer Documentation
> **前置**：3.2 TensorRT 输出显存、4.1 letterbox 几何信息
> **范围**：教学用普通检测张量；解码代码为 `.cu` 片段，需与推理工程接入。

## 1. 先写清楚输出契约

GPU 不知道某列代表框、分数还是关键点。**不能仅凭张量尺寸猜解码方式**，必须查模型导出说明。

本例约定：batch=1、float32、线性布局，每个候选有 `F = 4 + C` 个特征：

```text
[cx, cy, w, h, class_score_0, ..., class_score_(C-1)]
```

- 坐标已解码，是 letterbox 图像中的像素单位 `cxcywh`。
- 分数已经是概率，不再加 sigmoid，也没有额外 objectness。
- 每个候选只选择最高分的一个类别，不做 multi-label。
- 分数 `>= threshold` 保留；无效数值、非正宽高丢弃。

YOLOv5 的 objectness×class、未解码的 DFL、关键点模型、带 NMS 插件的输出均不属于此契约，需要单独适配。IO 为 HALF 时，也必须换成对应的 half 读取代码。

## 2. 两种布局，用 stride 区分

常见的输出可能是 `[1,K,F]`，也可能是 `[1,F,K]`。无需为了教学先转置整块输出，用两个元素步长描述：

| 布局 | candidate_stride | feature_stride |
|---|---:|---:|
| `[1,K,F]`（候选优先） | F | 1 |
| `[1,F,K]`（特征优先） | 1 | K |

第 i 个候选、第 f 个特征：

```text
data[i * candidate_stride + f * feature_stride]
```

这些是 **float 元素**步长，与 GpuMat 的字节 `step` 不同。特征优先时，相邻线程读取同一特征的相邻位置，有利于合并访存。

K/F 要从当前请求的已解析 shape 与模型契约取得。动态输入设置后，查询 context 的 `getTensorShape(output_name)`，不要把 engine 中的 `-1` 当元素数。数据相关的动态输出需要正确的输出分配器或容量策略，不在这个固定容量示例范围内。

## 3. 为什么需要 atomicAdd

每个候选由一个线程判断，只有少部分通过阈值。保留下来的线程需要一个唯一的写入槽位：

```cpp
int slot = atomicAdd(count, 1);
```

原子加返回加之前的值，因此所有通过的线程得到互不重复的位置。这样把稀疏候选压成 `[0, count)` 的紧凑数组。

**原子加只保证槽位唯一，不保证排列顺序**。每次运行的候选顺序都可能不同，所以保留 `candidate_id`，测试时按 ID 对齐，NMS 前按分数与 ID 排序。

## 4. 候选结构与 kernel

坐标逆变换采用 4.1 的实际缩放尺寸比：`new_w/src_w`、`new_h/src_h`。本例框坐标表示连续边界，逆变换只减 padding、除缩放比；不要把图像采样的半像素公式直接套到框边界上。

```cpp
#include <cuda_runtime.h>
#include <cstddef>
#include <cmath>

struct Candidate {
    int candidate_id;
    int class_id;
    float score;
    float x1, y1, x2, y2;  // 原图连续坐标，面积不加 1
};

__global__ void decodeKernel(
    const float* data, int K, int C,
    size_t candidate_stride, size_t feature_stride,
    float threshold, int capacity,
    int src_w, int src_h,
    int new_w, int new_h, int pad_x, int pad_y,
    int* count, Candidate* candidates)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i >= K) return;
    const float* base = data + size_t(i) * candidate_stride;
    float cx = base[0 * feature_stride];
    float cy = base[1 * feature_stride];
    float w  = base[2 * feature_stride];
    float h  = base[3 * feature_stride];
    if (!isfinite(cx) || !isfinite(cy) || !isfinite(w) || !isfinite(h)
        || w <= 0 || h <= 0) return;

    int cls = 0;
    float score = base[4 * feature_stride];
    if (!isfinite(score)) return;
    for (int c = 1; c < C; ++c) {
        float s = base[size_t(4 + c) * feature_stride];
        if (!isfinite(s)) return;
        if (s > score) { score = s; cls = c; }
    }
    if (score < threshold) return;

    float ix = float(src_w) / new_w, iy = float(src_h) / new_h;
    float x1 = (cx - w * 0.5f - pad_x) * ix;
    float y1 = (cy - h * 0.5f - pad_y) * iy;
    float x2 = (cx + w * 0.5f - pad_x) * ix;
    float y2 = (cy + h * 0.5f - pad_y) * iy;
    if (!isfinite(x1) || !isfinite(y1) || !isfinite(x2) || !isfinite(y2)) return;
    x1 = fminf(float(src_w), fmaxf(0.0f, x1));
    y1 = fminf(float(src_h), fmaxf(0.0f, y1));
    x2 = fminf(float(src_w), fmaxf(0.0f, x2));
    y2 = fminf(float(src_h), fmaxf(0.0f, y2));
    if (x2 <= x1 || y2 <= y1) return;

    int slot = atomicAdd(count, 1);
    if (slot >= capacity) return;  // 防越界，仍需报告溢出
    candidates[slot] = Candidate{i, cls, score, x1, y1, x2, y2};
}
```

所有几何参数和容量均由 host 检查为有效正值。`capacity=K` 是最容易正确验证的选择。若容量不足，原子到达次序决定谁被丢弃，**这不是按分数选 top-K**；生产代码应扩容或实现确定的 top-K，而不是默默截断。

## 5. 直接读取 TensorRT 的 d_output

不把完整输出下载回 CPU，又上传给 kernel：解码直接使用已绑定的 `d_output`，与 `enqueueV3` 放在同一 stream。

以下是接入片段。初始化时已经创建了每个请求槽位独立的 `d_count`、`d_candidates`，以及 pinned 的 `h_count`、`h_candidates`；每帧复用，结束后统一释放。

```cpp
#include <stdexcept>
#include <string>

void checkCuda(cudaError_t err)
{
    if (err != cudaSuccess) throw std::runtime_error(cudaGetErrorString(err));
}

// K、C、capacity、几何参数已经检查；本例 capacity >= K。
checkCuda(cudaMemsetAsync(d_count, 0, sizeof(int), stream)); // 每帧都清零
if (!context->enqueueV3(stream)) throw std::runtime_error("推理入队失败");

decodeKernel<<<(K + 255) / 256, 256, 0, stream>>>(
    static_cast<const float*>(d_output), K, C,
    candidate_stride, feature_stride, threshold, capacity,
    src_w, src_h, lb.new_w, lb.new_h, lb.pad_x, lb.pad_y,
    d_count, d_candidates);
checkCuda(cudaPeekAtLastError());

// 基线：先拿数量，再只下载有效候选。两个同步点，容易验证。
checkCuda(cudaMemcpyAsync(h_count, d_count, sizeof(int),
                          cudaMemcpyDeviceToHost, stream));
checkCuda(cudaStreamSynchronize(stream));
if (*h_count < 0 || *h_count > capacity)
    throw std::runtime_error("候选容量溢出，不能静默截断");
int n = *h_count;
if (n > 0) {
    checkCuda(cudaMemcpyAsync(h_candidates, d_candidates, size_t(n) * sizeof(Candidate),
                              cudaMemcpyDeviceToHost, stream));
    checkCuda(cudaStreamSynchronize(stream));
}
```

下载数量需要 CPU 等待，会引入额外调度开销。进阶版可固定下载整块候选容量和 count，在同一次完成事件之后消费；它少一个等待，但传输更多数据。通过测量决定，不要为了「拷贝最少」忽略同步成本。

## 6. NMS 先留在 CPU

解码是独立任务，很适合线程并行；NMS 存在候选间的抑制关系，不能让所有线程同时随意删除框。

先实现一个确定的 CPU 基线，再考虑 GPU NMS：

```cpp
#include <algorithm>
#include <vector>

float iou(const Candidate& a, const Candidate& b)
{
    float iw = std::max(0.0f, std::min(a.x2, b.x2) - std::max(a.x1, b.x1));
    float ih = std::max(0.0f, std::min(a.y2, b.y2) - std::max(a.y1, b.y1));
    float inter = iw * ih;
    float area_a = (a.x2 - a.x1) * (a.y2 - a.y1);
    float area_b = (b.x2 - b.x1) * (b.y2 - b.y1);
    float union_area = area_a + area_b - inter;
    return union_area > 0 ? inter / union_area : 0.0f;
}

std::vector<Candidate> classAwareNms(std::vector<Candidate> boxes, float threshold)
{
    std::sort(boxes.begin(), boxes.end(), [](const Candidate& a, const Candidate& b) {
        if (a.score != b.score) return a.score > b.score;
        return a.candidate_id < b.candidate_id;  // 分数相同的确定顺序
    });
    std::vector<Candidate> kept;
    for (const auto& box : boxes) {
        bool suppressed = false;
        for (const auto& other : kept) {
            if (box.class_id == other.class_id && iou(box, other) > threshold) {
                suppressed = true;
                break;
            }
        }
        if (!suppressed) kept.push_back(box);
    }
    return kept;
}
```

这是 class-aware greedy NMS，面积不加 1，IoU **大于**阈值才抑制。CPU 和 GPU 测试必须采用同一语义。调试打印候选数量、保留 ID、class、score、坐标，不能只看是否「画出框」。

## 7. 最小验证集与练习

人工构造 K=5、C=2 的张量（坐标都在图内），测试：

- 1 个分数低于阈值，丢弃。
- 2 个同类重叠框，NMS 留高分者。
- 1 个不同类重叠框，class-aware NMS 不删。
- 1 个远离的框，保留。

预期解码得到 4 个候选，NMS 后 3 个。分别用候选优先、特征优先布局，结果 ID 集合相同。再加入 NaN、负宽度、全过滤、恰好等于阈值等边界案例。

你的练习是：用同一张量做 CPU 参考解码，按 `candidate_id` 对齐 GPU 候选，逐字段比较。没有这一步，无法区分模型问题、布局问题与后处理问题。
