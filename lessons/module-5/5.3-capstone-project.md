# 5.3 综合项目：独立组织、调试和交付 GPU 推理流水线

> **对应 SLT**：我能独立编写并调试一个 TensorRT + OpenCV-CUDA 项目，复用部署库的模式。
> **课时类型**：Developer Documentation
> **前置**：Module 1–4、5.1 配置与 5.2 计时
> **资产**：[`5.3-pipeline-contract.hpp`](../../assets/code-examples/5.3-pipeline-contract.hpp)，接口脚手架，不包含推理实现。

## 项目目标与范围

从视频取得 BGR 帧，经预处理、推理、解码、CPU NMS，再在**对应原帧**画框输出。相同程序可按 YAML 选择 CPU/OpenCV CUDA/TensorRT，并在 TensorRT 路径切换单路与多路。

不引用业务仓库、不接相机或串口。先把正确性和资源生命周期写明，再增加吞吐。这是独立实现作业，不是把一个尚未验证的整包工程宣称为成品。

本节提供接口、工程布局、CMake 参考、调度代码和验收流程。下文 `build/detector` 命令是**你实现并构建后的目标 CLI**；课程当前没有附带已可运行的完整 detector、ONNX 或 engine。

### 第一版模型契约

- batch=1、一个图像输入和一个检测输出；NCHW FP32、TensorRT IO 为 DEVICE、LINEAR。
- 输入 resize/letterbox、RGB、归一化、padding 全部按模型契约，不默认采用任意 YOLO 配置。
- 输出限定 `[1,K,4+C]` 或 `[1,4+C,K]`，xywh、已是类别分数，无独立 objectness；K 在入队前已解析。
- GPU 解码使用 4.2，CPU 同类 NMS 采用相同排序与边界语义。
- 第一阶段用静态 ONNX。若源模型是动态尺寸，构建时添加合法 optimization profile；运行时选定输入尺寸，禁止用「把 -1 替成 1」猜维度。

选择符合该契约的模型，或先编写明确的适配层。含 DFL、关键点、NMS 插件、多输出或数据相关动态输出的模型不直接适用；不支持时启动失败，而不是碰巧画出几个框。

## 2. 把请求作为接口单位

复制课程的 `5.3-pipeline-contract.hpp` 到项目 include。它定义：

```cpp
// 摘要；完整定义在资产文件。
RequestToken submit(Frame frame);
bool ready(const RequestToken& token);
Result collect(const RequestToken& token);
```

约定比函数名更重要：

| 接口 | 必须保证 |
|---|---|
| `submit` | 使用空闲槽位，保留原图/几何/时间戳；无空槽时拒绝，不能覆盖旧请求 |
| `ready` | 验证 slot、generation、frame_id；`cudaErrorNotReady` 是未完成，其他 CUDA 错误必须报出 |
| `collect` | 只消费一次；等待完成、读取候选、CPU NMS，生成拥有主机结果的 Result 后才释放槽位 |
| `capacity` | sync/async 返回 1，parallel 返回配置 slots；不是同时处理的 batch size |

`generation` 随每次复用递增，旧 token 必须失效。输入 Mat 在途时不能修改；视频采集若复用内存，提交前做独立快照。输出画框应 clone 原图，不能把下一请求仍在读的图像写坏。

CPU backend 可以同步算完并让 ready 立即为 true，仍保持相同 Result/frame_id 契约。OpenCV DNN 不共享同一个 Net 给并发线程；本版只支持其单路 sync。

## 3. 让编译选项与运行时选择对上

下面是 **CMake 参考骨架**，需要先实现上述源文件才能构建。GPU 选项明确依赖可用 Toolkit；CPU-only 不启用 CUDA 语言。构建 engine 需要 nvonnxparser，运行时所需插件另按模型链接/注册。

```cmake
cmake_minimum_required(VERSION 3.22)
project(coach_detector LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
option(COACH_WITH_GPU "Build CUDA preprocessing kernels" ON)
option(COACH_WITH_TENSORRT "Build TensorRT backend and builder" ON)

find_package(OpenCV REQUIRED COMPONENTS core imgproc videoio dnn
             OPTIONAL_COMPONENTS cudaarithm cudaimgproc cudawarping)
find_package(yaml-cpp CONFIG REQUIRED)
if(TARGET yaml-cpp::yaml-cpp)
  set(YAML_TARGET yaml-cpp::yaml-cpp)
else()
  set(YAML_TARGET yaml-cpp)
endif()

add_library(pipeline src/config.cpp src/preprocess_cpu.cpp
            src/decode_cpu.cpp src/opencv_backend.cpp)
target_include_directories(pipeline PUBLIC include ${OpenCV_INCLUDE_DIRS})
target_link_libraries(pipeline PUBLIC ${OpenCV_LIBS} ${YAML_TARGET})
target_compile_definitions(pipeline PUBLIC
  COACH_WITH_GPU=$<BOOL:${COACH_WITH_GPU}>
  COACH_WITH_TENSORRT=$<BOOL:${COACH_WITH_TENSORRT}>)

if(COACH_WITH_GPU)
  enable_language(CUDA)
  find_package(CUDAToolkit REQUIRED)
  foreach(module opencv_cudaarithm opencv_cudaimgproc opencv_cudawarping)
    if(NOT TARGET ${module})
      message(FATAL_ERROR "Missing ${module}: select a CUDA-enabled OpenCV")
    endif()
  endforeach()
  target_sources(pipeline PRIVATE src/preprocess_cuda.cu src/decode_cuda.cu)
  set_target_properties(pipeline PROPERTIES CUDA_STANDARD 17 CUDA_STANDARD_REQUIRED ON)
  target_compile_options(pipeline PRIVATE $<$<COMPILE_LANGUAGE:CUDA>:-lineinfo>)
  target_link_libraries(pipeline PUBLIC CUDA::cudart
    opencv_cudaarithm opencv_cudaimgproc opencv_cudawarping)
endif()

if(COACH_WITH_TENSORRT)
  if(NOT COACH_WITH_GPU)
    message(FATAL_ERROR "This TensorRT build requires COACH_WITH_GPU=ON")
  endif()
  find_path(TRT_INCLUDE NvInfer.h HINTS ${TENSORRT_ROOT} PATH_SUFFIXES include REQUIRED)
  find_library(TRT_INFER nvinfer HINTS ${TENSORRT_ROOT} PATH_SUFFIXES lib lib/x64 REQUIRED)
  find_library(TRT_PARSER nvonnxparser HINTS ${TENSORRT_ROOT} PATH_SUFFIXES lib lib/x64 REQUIRED)
  target_sources(pipeline PRIVATE src/trt_backend.cpp src/engine_builder.cpp)
  target_include_directories(pipeline PRIVATE ${TRT_INCLUDE})
  target_link_libraries(pipeline PRIVATE ${TRT_INFER} ${TRT_PARSER})
endif()
add_executable(detector src/main.cpp)
target_link_libraries(detector PRIVATE pipeline)
```

GPU 配置构建示例（算力 86 对应本机 3060 Ti，其他设备改成对应值）：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_ARCHITECTURES=86 \
  -DOpenCV_DIR="$HOME/opt/opencv-cuda/lib/cmake/opencv4" \
  -DTENSORRT_ROOT="$HOME/tensorrt/TensorRT-10.10.0.31"
cmake --build build -j
./build/detector --help
```

最后应打印帮助，支持 `--config`、`--input`、`--output`、`--bench`、`--timings`。CPU-only 构建使用另一个 build 目录，设 `COACH_WITH_GPU=OFF`、`COACH_WITH_TENSORRT=OFF` 并选 CPU OpenCV。

CUDA 必须匹配实际 TensorRT 分发包及其运行环境；Module 4 独立 kernel 测试用 nvcc 11.8，不构成 TensorRT 10.10 的兼容声明。头文件、链接库和运行时加载库必须来自一致安装。

## 4. 先检查 engine，再计算缓冲大小

TensorRT 初始化检查顺序：

1. 校验可信 engine/cache manifest；需要插件时先加载和注册，再反序列化。
2. 创建 context，检查返回对象非空；确认 IO 数量、名称、方向、`getTensorDataType`、`getTensorFormat`、`getTensorLocation`。
3. 动态输入先确认尺寸在 profile 内，调用 `setOptimizationProfileAsync`、`setInputShape` 并检查返回值；profile 切换与推理之间有正确流依赖。context 不在执行时才可重配置。
4. 对本版非 shape-tensor 输入，检查 `inferShapes(0, nullptr)` 没有报错或缺少输入；查询 **context** 的 `getTensorShape`。
5. 维度全部为正才算元素数；若输出仍有 -1，拒绝本版模型。进阶实现要使用 `IOutputAllocator` 或正确容量策略，不可先随便分配再 enqueue。
6. 按 shape × dtype 大小分配 device/pinned 缓冲，检查乘法溢出；绑定 `setTensorAddress` 并检查 bool。

用以下函数替代「负数维度转 size_t」的隐患：

```cpp
#include <NvInferRuntime.h>
#include <cstddef>
#include <limits>
#include <stdexcept>
size_t checkedFloatBytes(nvinfer1::Dims dims) {
    if (dims.nbDims <= 0) throw std::runtime_error("expected a resolved non-scalar tensor");
    size_t elements = 1;
    for (int i = 0; i < dims.nbDims; ++i) {
        if (dims.d[i] <= 0) throw std::runtime_error("unresolved/empty dimension");
        size_t d = static_cast<size_t>(dims.d[i]);
        if (elements > std::numeric_limits<size_t>::max() / d)
            throw std::runtime_error("tensor volume overflow");
        elements *= d;
    }
    if (elements > std::numeric_limits<size_t>::max() / sizeof(float))
        throw std::runtime_error("tensor byte size overflow");
    return elements * sizeof(float);
}
// 调用前已检查 FLOAT + LINEAR + DEVICE：
// auto bytes = checkedFloatBytes(context->getTensorShape(output_name));
```

此函数不是通用 dtype/向量化格式分配器。FP16 builder tactics 与 HALF IO 是不同问题；后者不能用 sizeof(float) 推导或把指针强转交给 4.1/4.2。

## 5. 每个 slot 拥有完整状态

```text
FREE → SUBMITTING → IN_FLIGHT → COLLECTING → FREE
                  出错 → FAILED（停止提交，等待/清理已入队工作）
```

每 slot 至少拥有：context、stream、完成 event、device input/output、GpuMat/页锁定上传缓冲、device count/candidates、pinned 输出、原图、frame_id/generation、letterbox 几何、时间戳。

- runtime、engine 和 logger 比 contexts 活得更久；同一 context 不同时服务两个请求。
- 推荐由 `cv::cuda::Stream` 持有流，通过 `StreamAccessor::getStream` 取 raw stream 给 TensorRT/CUDA。不要再对这个 raw handle 重复 cudaStreamDestroy。
- GpuMat upload、融合 kernel、`enqueueV3`、解码与 D2H 用同一流。跨流版本必须有 event wait，不可依赖「两个函数调用先后顺序」。
- pinned 上传源在传输完成前不能覆盖，输入/输出/几何直到消费完成都不能复用。
- `cudaEventRecord` 放在本请求最后的传输后；回收才等待它，不在每一步 device-wide 同步。
- 一份 engine 不意味着只需一份全部显存；多个 context 的 activation/scratch、pinned 内存与图像都计入预算。

GPU 解码可以先按固定 capacity 下载 count 和整块候选缓冲，再 record 完成 event，避免 CPU 先读 count 的额外同步点。消费时只解释有效前缀；若 count > capacity，按 4.2 规则报溢出，不能把任意截断当 top-K。若选择仅下载有效候选，需要承认读 count 引入的同步/两阶段调度成本。

任何 CUDA/TensorRT 返回值都检查，包括异步操作在回收时暴露的错误。submit 中途失败可能已有工作在飞行；不能把 slot 标 FREE 后立即释放指针。使用 RAII/回滚守卫先处理在途工作；析构不抛异常。正常退出必须先回收全部结果，严重 CUDA 故障则停止本次运行并记录失败。

## 6. 调度代码必须包含背压与 drain

下面代码使用资产接口，后端实现由你补齐。输入已经预读且不再修改；生产采集复用 Mat 时应 clone。

```cpp
#include "pipeline_contract.hpp"
#include <chrono>
#include <deque>
#include <stdexcept>
#include <utility>
using Clock = std::chrono::steady_clock;
std::int64_t nowNs() {
    return std::chrono::duration_cast<std::chrono::nanoseconds>(
        Clock::now().time_since_epoch()).count();
}
std::vector<coach::Result> runMeasured(
    coach::Pipeline& pipeline, const std::vector<cv::Mat>& images,
    bool collect_immediately) { // sync=true; async/parallel=false
    if (pipeline.capacity() == 0) throw std::runtime_error("zero pipeline capacity");
    std::deque<coach::RequestToken> pending;
    std::vector<coach::Result> results;
    results.reserve(images.size());
    auto collectOldest = [&] {
        auto result = pipeline.collect(pending.front());
        if (result.frame_id != pending.front().frame_id)
            throw std::runtime_error("frame/result mismatch");
        results.push_back(std::move(result));
        pending.pop_front();
    };
    for (size_t i = 0; i < images.size(); ++i) {
        coach::Frame frame{static_cast<std::int64_t>(i), images[i], nowNs()};
        if (pending.size() == pipeline.capacity()) collectOldest();
        pending.push_back(pipeline.submit(std::move(frame)));
        if (collect_immediately) collectOldest();
    }
    while (!pending.empty()) collectOldest(); // 尾请求全部完成，不只等最后提交函数返回
    if (results.size() != images.size()) throw std::runtime_error("lost result");
    return results;
}
```

`collect` 内部记录 5.2 的 done_ns；对原始输出/候选的读取必须在完成后。此调度按提交顺序消费，可能产生 head-of-line 等待，这是明确的策略而非程序错误。进阶可按完成顺序回收，再用 frame_id 保序输出；仍必须保留不可变原图，不能对最新视频帧直接画旧结果。

**sync 模式**调用时设 `collect_immediately=true`，每提交一帧立即 collect。**单 slot async 模式**设 false，允许 CPU 在 collect 前做其他工作，但不会重叠两帧 GPU 请求。**parallel 模式**设 false，使用上述多槽调度。单路时正确不代表多路正确。

预热也使用同一回收协议，全部完成后丢弃其计时数据，再运行 measured。不能把 warmup 的旧输出记到 measured frame_id 上。

## 7. 分三次集成，失败时只回退一层

| 里程碑 | 做什么 | 验证 |
|---|---|---|
| M0 CPU 基线 | CPU 预处理 → OpenCV DNN CPU → CPU 解码/NMS | 颜色、几何、类别、每帧结果可解释 |
| M1 TRT 单路 | CPU 前后处理，FLOAT IO，sync | 同一 NCHW 的原始推理输出；冷启动/缓存再次加载 |
| M2 GPU 驻留 | 替换预处理/解码，各改一个变量 | 4.4 分层 parity、memcheck |
| M3 多路 | 2/4 slots、不同输入连续提交 | frame_id、几何、结果对齐与 fill/drain |

不要把 FP16、多路和融合 kernel 在同一次改动里全加上。OpenCV DNN CUDA 是独立 backend 对照，初始化时设置：

```cpp
// net 是用同一 ONNX 读入的 cv::dnn::Net。
net.setPreferableBackend(cv::dnn::DNN_BACKEND_CUDA);
net.setPreferableTarget(cv::dnn::DNN_TARGET_CUDA);
// CPU 路径则用 DNN_BACKEND_OPENCV + DNN_TARGET_CPU。
```

该 backend 有自己的内部 CUDA 流；不能用你 TensorRT slot 的 event 计时去代表 OpenCV DNN forward。其输入输出边界、可能的 CPU fallback 按 5.1 记录，CPU wall-clock 仍用于最终端到端对照。

## 8. 用证据定位错误

先用 Debug/RelWithDebInfo 小样本；工具运行结束后看输出与退出码。以下命令只在你完成对应可执行文件后可运行：

```bash
./build/detector --config configs/deploy.yaml --input data/input.mp4 \
  --output reports/result.mp4
compute-sanitizer --tool memcheck --error-exitcode 99 \
  ./build/detector --config configs/deploy.yaml --input data/input.mp4 --bench
```

正常应有逐阶段摘要、提交/回收数量一致、输出视频帧对应原帧；memcheck 应报告零错误。sanitizer 下的耗时不作性能数据。

定位顺序：

| 症状 | 最小诊断 |
|---|---|
| 一开始无设备/无法载库 | 检查可见设备、ldd、TensorRT/CUDA/插件版本；尚不查解码 |
| parser/build 失败 | 打印完整 parser/builder 日志；检查算子、profile、精度与 workspace |
| 显存申请异常巨大 | 查看每个 resolved dim，禁止 -1 转无符号 |
| 颜色/框全错 | 导出同一帧 NCHW，再固定原始输出对比 CPU/GPU 解码 |
| 单路正常，多路错帧 | slot/token/generation、pinned 源覆盖、event 与几何生命周期 |
| 尾帧消失 | 看 submitted/completed/consumed，确认循环结束后 drain |
| CUDA 非法地址在后续 API 才报 | 调试时在可疑 kernel 后检查 launch + stream 同步，缩小范围 |
| 结果正确但没有变快 | 5.2 的 pipeline 时间与时间线，确认传输、同步和 CPU NMS 瓶颈 |

`CUDA_LAUNCH_BLOCKING=1` 可在新进程里临时定位异步错误，会改变时序并掩盖竞争；诊断后关闭再跑压力测试。TensorRT 的 `setDebugSync` 不用于解决 `enqueueV3` 的异步定位（该设置对 enqueueV3 无效）。不要用生产中的逐层同步换取「看起来稳定」。

## 9. 综合项目验收

### 必须提交

1. 独立源码、CMake、README：干净目录能按命令构建；说明模型来源/契约和依赖版本。
2. A–E 的配置与启动校验；不可用配置明确失败，后端不静默替换。
3. 视频或逐帧结果：frame_id 与原图对齐；含无检测帧、横竖/奇数尺寸和不同内容的连续帧。
4. 分层 parity、容量不足、陈旧 token/重复 collect、1/2/4 slots、未整除 slot 数的 N、正常/异常退出测试。
5. submitted=completed=consumed=N，无重复/漏帧；正常停止先 drain，再销毁资源。
6. memcheck 报告、配置副本、原始计时 CSV 和 5.2 统计；至少三次测量，明确哪些是编译/模拟/真机。
7. 一页调试记录：现象 → 最小复现 → 根因 → 修正 → 回归测试。至少一次生命周期或契约问题，不只截图。

### 评分标准

| 维度 | 分值 | 满分依据 |
|---|---:|---|
| 正确性与模型契约 | 30 | 分层测试、几何/类别/NMS、边界与明确容差 |
| 生命周期与调度 | 25 | 每槽隔离、无错帧、背压/drain、错误清理 |
| 配置与部署 | 15 | 可复现构建、fail-fast、缓存 manifest、依赖说明 |
| 性能测量 | 20 | 正确边界、原始数据、延迟分位/FPS、单变量对照 |
| 调试解释 | 10 | 有可复现的根因和回归证据 |

建议通过线 80 分。**结果错帧、显存越界或漏回收属于必须修复项，不靠其他分抵消。** 不要求 GPU 比 CPU 更快，也不要求 slots 越多越好；可解释的负结果同样有效。
