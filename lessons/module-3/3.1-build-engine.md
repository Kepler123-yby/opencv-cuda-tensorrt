# 3.1 从 ONNX 构建并缓存 TensorRT engine

> **对应 SLT**：我能从 ONNX 构建并缓存 TensorRT engine，并反序列化用于推理。
> **课时类型**：Developer Documentation
> **版本**：TensorRT 10.10.0.31（API 已核对）
> **前置**：1.1 环境、1.2 CMake 检测、2.2 预处理

---

## engine 是什么

TensorRT 不直接跑 ONNX。中间要经过一次**构建（build）**：把 ONNX 网络解析、优化、按你的 GPU 架构生成一份专属的推理计划，这就是 **engine**。

engine 可以**序列化**成一串字节存到磁盘。之后每次启动直接加载，跳过构建。为什么要缓存？因为构建很慢（几十秒到几分钟），而且结果在**同一个 TensorRT 版本 + 同一张 GPU** 上是稳定的。

一个必须记住的约束：**engine 与 TensorRT 版本、GPU 架构强绑定**。10.10.0.31 构建出的 `.engine` 拿到别的 TensorRT 版本上会加载失败。所以环境升级后，删掉缓存重新构建即可。

## 构建流水线与四个对象

构建一条链，涉及四个对象，顺序不能乱：

```text
IBuilder ──► INetworkDefinition ──► IParser ──► 解析 ONNX
   │
   └──► IBuilderConfig（FP16、workspace）──► buildSerializedNetwork ──► 序列化字节
```

| 对象 | 职责 |
|---|---|
| `IBuilder` | 构建器入口 |
| `INetworkDefinition` | 网络定义，Parser 往里填 |
| `nvonnxparser::IParser` | 把 ONNX 解析进网络 |
| `IBuilderConfig` | 构建选项：精度、显存池 |

运行时侧则换一套对象：

```text
IRuntime ──► deserializeCudaEngine ──► ICudaEngine ──► createExecutionContext ──► IExecutionContext
```

> **TensorRT 10 提醒**：`createNetworkV2` 的参数传 `0` 即可。`NetworkDefinitionCreationFlag::kEXPLICIT_BATCH` 在 10.x **已废弃**，因为 explicit batch 永远是开启的。照抄 8.x 旧例程会得到一个废弃告警。

## 一个必须实现的 Logger

TensorRT 通过 `ILogger` 回报构建与运行时的信息。它是**必填**的，不实现就没法创建 Builder。

```cpp
class Logger : public nvinfer1::ILogger
{
public:
    void log(Severity severity, const char* msg) noexcept override
    {
        if (severity <= Severity::kWARNING)   // 屏蔽 INFO，保留警告与错误
            std::cout << "[TRT] " << msg << "\n";
    }
};
```

调试构建失败时，先把阈值放开到 `kINFO`，能看到更多细节。

## 构建函数

```cpp
#include <NvInfer.h>
#include <NvOnnxParser.h>

#include <fstream>
#include <memory>
#include <stdexcept>
#include <vector>

std::vector<char> buildEngine(const std::string& onnx_path, Logger& logger)
{
    auto builder = std::unique_ptr<nvinfer1::IBuilder>(
        nvinfer1::createInferBuilder(logger));
    if (!builder) throw std::runtime_error("创建 Builder 失败");

    // TensorRT 10：explicit batch 恒开启，传 0 即可
    auto network = std::unique_ptr<nvinfer1::INetworkDefinition>(
        builder->createNetworkV2(0));
    if (!network) throw std::runtime_error("创建 Network 失败");

    auto parser = std::unique_ptr<nvonnxparser::IParser>(
        nvonnxparser::createParser(*network, logger));
    if (!parser) throw std::runtime_error("创建 ONNX Parser 失败");

    if (!parser->parseFromFile(onnx_path.c_str(),
            static_cast<int>(nvinfer1::ILogger::Severity::kWARNING)))
        throw std::runtime_error("解析 ONNX 失败: " + onnx_path);

    auto config = std::unique_ptr<nvinfer1::IBuilderConfig>(
        builder->createBuilderConfig());
    if (!config) throw std::runtime_error("创建 BuilderConfig 失败");

    // 模型是 fp16 时允许半精度；workspace 池上限 1 GiB
    config->setFlag(nvinfer1::BuilderFlag::kFP16);
    config->setMemoryPoolLimit(nvinfer1::MemoryPoolType::kWORKSPACE, 1ULL << 30);

    auto serialized = std::unique_ptr<nvinfer1::IHostMemory>(
        builder->buildSerializedNetwork(*network, *config));
    if (!serialized) throw std::runtime_error("构建 engine 失败");

    const char* begin = static_cast<const char*>(serialized->data());
    return std::vector<char>(begin, begin + serialized->size());
}
```

> **TensorRT 10 API 差异**：`setMemoryPoolLimit(MemoryPoolType::kWORKSPACE, ...)` 取代了旧的 `setMaxWorkspaceSize(...)`。`setFlag(BuilderFlag::kFP16)` 的用法未变。

## 缓存：存在且不旧，就直接加载

用一份同名 `.engine` 作缓存。判断「不旧」的方式是比修改时间：ONNX 比缓存新，就重建。

```cpp
#include <filesystem>

std::vector<char> readFile(const std::string& path)
{
    std::ifstream f(path, std::ios::binary | std::ios::ate);
    if (!f) throw std::runtime_error("找不到文件: " + path);
    std::streamsize size = f.tellg();
    f.seekg(0, std::ios::beg);
    std::vector<char> buf(static_cast<size_t>(size));
    f.read(buf.data(), size);
    return buf;
}

void writeFile(const std::string& path, const void* data, size_t size)
{
    std::ofstream f(path, std::ios::binary);
    f.write(static_cast<const char*>(data), static_cast<std::streamsize>(size));
}
```

主流程：

```cpp
std::vector<char> loadOrBuild(const std::string& onnx, Logger& logger)
{
    std::string cache = onnx.substr(0, onnx.find_last_of('.')) + ".engine";

    std::error_code ec;
    bool cache_valid =
        std::filesystem::is_regular_file(cache, ec) &&
        std::filesystem::last_write_time(cache, ec) >=
        std::filesystem::last_write_time(onnx, ec);

    if (cache_valid) {
        std::cout << "复用缓存: " << cache << "\n";
        return readFile(cache);
    }

    std::cout << "从 ONNX 构建 engine（首次较慢）...\n";
    std::vector<char> data = buildEngine(onnx, logger);
    writeFile(cache, data.data(), data.size());
    std::cout << "已写入缓存: " << cache << "\n";
    return data;
}
```

## 反序列化，并打印张量信息

加载后，第一件事是把输入输出的**名字、形状、类型**打印出来。后面绑定缓冲区全靠这些名字。

```cpp
int main(int argc, char** argv)
{
    Logger logger;
    const std::string onnx = argv[1];

    std::vector<char> engine_data = loadOrBuild(onnx, logger);

    auto runtime = std::unique_ptr<nvinfer1::IRuntime>(
        nvinfer1::createInferRuntime(logger));
    auto engine = std::unique_ptr<nvinfer1::ICudaEngine>(
        runtime->deserializeCudaEngine(engine_data.data(), engine_data.size()));
    if (!engine) throw std::runtime_error("反序列化 engine 失败");

    std::cout << "IO 张量 (" << engine->getNbIOTensors() << " 个):\n";
    for (int i = 0; i < engine->getNbIOTensors(); ++i) {
        const char* name = engine->getIOTensorName(i);
        auto mode = engine->getTensorIOMode(name);
        auto dims = engine->getTensorShape(name);
        std::cout << "  " << name
                  << (mode == nvinfer1::TensorIOMode::kINPUT ? " (输入)" : " (输出)")
                  << " 形状 [";
        for (int d = 0; d < dims.nbDims; ++d)
            std::cout << dims.d[d] << (d + 1 < dims.nbDims ? ", " : "");
        std::cout << "]\n";
    }
    return 0;
}
```

> **TensorRT 10 提醒**：IO 张量按**名字**访问（`getIOTensorName` / `getTensorShape(name)`）。8.x 的 binding index 体系已移除。

## 验证

编译时链接 `nvinfer` 与 `nvonnxparser`（见 1.2 的 CMake），然后：

```bash
./build-engine model.onnx
```

预期输出：

```
从 ONNX 构建 engine（首次较慢）...
已写入缓存: model.engine
IO 张量 (2 个):
  images (输入) 形状 [1, 3, 640, 640]
  output0 (输出) 形状 [1, 84, 8400]
```

再跑一次，应改为 `复用缓存: model.engine` 且**明显更快**。这就是缓存在起作用。

**判断标准**：第二次运行不再出现「从 ONNX 构建」，且张量名与你的模型一致。

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `解析 ONNX 失败` | ONNX 用了 TensorRT 不支持的算子 | 打开 Parser 的 `kINFO` 日志看具体算子 |
| 构建时显存不足 | workspace 上限过大或模型过大 | 调小 `setMemoryPoolLimit` |
| 反序列化返回空 | 缓存来自别的 TensorRT 版本 / GPU | 删除 `.engine` 重建 |
| 张量形状带 `-1` | 模型是动态 shape | 正常，需在 3.2 用 `setInputShape` 指定 |
| 第二次仍重新构建 | 缓存路径或时间判断错 | 检查 ONNX 与 `.engine` 是否同目录同名 |
