# 3.2 分配缓冲区，在 CUDA 流上执行推理

> **对应 SLT**：我能分配输入输出显存与页锁定内存，并在 CUDA 流上执行推理。
> **课时类型**：Developer Documentation
> **版本**：TensorRT 10.10.0.31，使用 TensorRT 10 的按名字绑定 API
> **前置**：[3.1 构建并缓存 engine](3.1-build-engine.md)、2.2 预处理、2.3 内存传输

本节把“已经加载的 Engine”变成“能完成一次推理的程序”。先理解数据在哪里、尺寸从哪里来，再按步骤分配、绑定、执行和验证。文末提供不依赖上一节辅助函数的完整 C++ 示例与编译命令。

**本节示例的边界**：一个普通数据输入、一个输出，I/O 位于 GPU，类型都是 `kFLOAT`（FP32），格式都是 `kLINEAR`（线性布局），没有用于形状推导的 I/O。支持静态形状，以及设置输入尺寸后能推导出输出尺寸的动态形状。其他模型会明确报错，而不是猜测类型或分配大小。

模型文件名中的 `fp16`、Builder 的 `kFP16` 标志，都不能证明输入输出也是 FP16。**I/O 类型必须查询 Engine。** 多输入、多输出、FP16 I/O、形状张量、数据依赖输出，需要扩展此示例，不能直接套用。

---

## 先看数据流：CPU 准备数据，GPU 计算，CPU 读取结果

```text
CPU / 主机内存                         GPU / 显存

h_in：预处理后的输入
        │
        └──── H2D（Host to Device） ──► d_in：输入张量
                                            │
                                   context->enqueueV3(stream)
                                            │
h_out：可供 CPU 读取的结果 ◄── D2H ─── d_out：输出张量
        │
        └── 等待 stream 完成后，才可以读取
```

这里有四块内存，不是两块：`h_in`、`h_out` 是 CPU 可直接访问的主机内存，`d_in`、`d_out` 是交给 TensorRT 的显存。名字里的 `h` / `d` 只是代码命名约定，不是 C++ 语法。

还有三个对象需要分清：

| 对象 | 负责什么 | 不负责什么 |
|---|---|---|
| `ICudaEngine` | 已构建的网络计划、权重和 I/O 元信息 | 不直接执行一次推理 |
| `IExecutionContext` | 当前执行状态、实际输入形状、张量地址，发起推理 | 不替你读取图片或预处理 |
| `cudaStream_t` | CUDA 工作的执行队列，保证队列内的依赖顺序 | 不是缓冲区，也不是 CPU 线程 |

一个 Engine 可以创建多个 Context，它们可共享 Engine 权重，但各自需要执行状态。不要把同一个 Context 当成可在多个 stream 上随意并发复用的对象。

本节使用默认的 `createExecutionContext()` 内存管理策略：TensorRT 管理 Context 所需的内部执行内存；我们分配的是应用的 I/O 缓冲区。**输入加输出的字节数，不等于推理所需的总显存。** [来源 S1]

## 第 1 步：加载 Engine，创建执行上下文

上一节保存的是 `.engine` 二进制文件。读取它后，通过 Runtime 反序列化，再创建 Context：

```cpp
Logger logger;
auto runtime = std::unique_ptr<nvinfer1::IRuntime>(
    nvinfer1::createInferRuntime(logger));
if (!runtime) throw std::runtime_error("创建 Runtime 失败");

auto engine = std::unique_ptr<nvinfer1::ICudaEngine>(
    runtime->deserializeCudaEngine(engine_data.data(), engine_data.size()));
if (!engine) throw std::runtime_error("反序列化 Engine 失败");

auto context = std::unique_ptr<nvinfer1::IExecutionContext>(
    engine->createExecutionContext());
if (!context) throw std::runtime_error("创建 Context 失败");
```

这段中的 `Logger` 和 `engine_data` 会在完整示例中定义。只加载自己构建或可信来源的 Engine。

**生命周期**：Logger 保持有效；Runtime 在 Engine 之后销毁；Engine 在 Context 之后销毁；Context 与缓冲区必须保持有效直到 GPU 工作完成。按 `logger → runtime → engine → context` 顺序声明局部变量，C++ 会按相反顺序销毁它们。[来源 S1、S2]

## 第 2 步：从 Engine 查询输入输出，而不是写死名字

```cpp
for (int i = 0; i < engine->getNbIOTensors(); ++i) {
    const char* name = engine->getIOTensorName(i);
    auto mode   = engine->getTensorIOMode(name);
    auto shape  = engine->getTensorShape(name);
    auto dtype  = engine->getTensorDataType(name);
    auto format = engine->getTensorFormat(name);
    auto where  = engine->getTensorLocation(name);
    // 打印并核对这些信息，再决定如何分配。
}
```

这些信息来自**已经构建的 Engine**，不是来自对模型名称的猜测。本机实际运行仓库的 `homework/tensorrt/model/model.engine`，查询结果是：

```text
images ：INPUT，FP32，LINEAR，DEVICE，[1,3,480,640]
output0：OUTPUT，FP32，LINEAR，DEVICE，[1,21,6300]
```

所以这个模型不能照搬常见的 `[1,3,640,640] → [1,84,8400]` 示例。尤其不能仅凭输出的 `21` 个通道猜测其业务含义，后处理要回到模型导出定义核对。

逐项理解元信息：

| 信息 | 为什么必须知道 |
|---|---|
| 名字，如 `images` | `setInputShape`、`setTensorAddress` 都按名字操作 |
| 输入还是输出 | 决定拷贝方向：H2D 或 D2H |
| 形状，如 `[1,3,640,640]` | 用于计算元素数量；动态维度还需设置实际值 |
| 类型，如 `kFLOAT` / `kHALF` | 一个元素分别占 4 / 2 字节；CPU 也必须按对应类型解释 |
| 格式，如 `kLINEAR` | 向量化格式可能有通道填充，不能一律按维度乘积算字节数 |
| 位置，`kDEVICE` / `kHOST` | 决定应绑定显存还是主机地址 |

完整示例会检查这些条件，并拒绝多个输入或输出。原来“循环里不断覆盖 `input_name` / `output_name`”的写法只会留下最后一个张量，不能用于多 I/O 模型。[来源 S1]

## 第 3 步：确定本次推理的实际形状

### 3.1 静态形状：直接使用已确定的尺寸

如果 Engine 的输入是 `[1,3,640,640]`，这次输入就必须匹配这个尺寸。这里的 `1` 是 batch，`3` 是通道，两个 `640` 是高和宽；是否确实为 NCHW，还要核对模型导出约定和预处理流程。

静态模型不需要为了运行而重新设置输入形状。

### 3.2 动态形状：实际值来自调用方，允许范围来自 profile

若 Engine 输入是 `[-1,3,-1,-1]`：

- `-1` 是“运行时决定”的占位符，不是一个可分配的长度。
- `[1,3,640,640]` 是应用这次准备送入的数据尺寸，**不是把所有 `-1` 随便改成 `1`**。
- 该尺寸必须落在构建时 optimization profile 的 MIN/MAX 范围内；静态维度也必须匹配。
- 运行时不能给一个没有相应 profile 的 Engine 补建 profile，构建配置见 3.1。

尺寸从哪里查？模型导出/预处理约定给出应该使用的尺寸；Engine 可以告诉你 profile 允许的范围：

```cpp
auto min_dims = engine->getProfileShape(input_name, 0,
    nvinfer1::OptProfileSelector::kMIN);
auto opt_dims = engine->getProfileShape(input_name, 0,
    nvinfer1::OptProfileSelector::kOPT);
auto max_dims = engine->getProfileShape(input_name, 0,
    nvinfer1::OptProfileSelector::kMAX);
```

MIN/MAX 是合法范围，OPT 是构建时的优化目标，不表示本次必须使用 OPT。检查返回 rank 是否有效，再逐维核对。以上查询针对已有 profile 的动态输入。

示例只使用 profile 0，动态模型的顺序如下：

```cpp
// stream 已显式创建；profile 切换和后面的推理使用同一条 stream。
if (!context->setOptimizationProfileAsync(0, stream))
    throw std::runtime_error("选择 profile 0 失败");

nvinfer1::Dims actual = engine->getTensorShape(input_name);
// 示例：由调用方传入 1 3 640 640，而不是自动猜测尺寸。
actual.d[0] = 1;
actual.d[1] = 3;
actual.d[2] = 640;
actual.d[3] = 640;
if (!context->setInputShape(input_name, actual))
    throw std::runtime_error("设置输入形状失败");
```

上面的四维片段只是说明；完整程序按模型 rank 读取命令行参数。`setInputShape` 成功不等于整个网络的形状都已合法。下一步需要检查形状推导结果。[来源 S2]

### 3.3 输出尺寸要从 Context 查询

```cpp
if (context->inferShapes(0, nullptr) != 0)
    throw std::runtime_error("形状推导失败或输入信息不完整");

auto in_dims  = context->getTensorShape(input_name);
auto out_dims = context->getTensorShape(output_name);
```

**Engine 给出构建时形状；Context 给出当前执行形状。** 动态模型应在设置实际输入后，使用 Context 的输出形状分配缓冲区。

若输出仍有 `-1`，先区分原因：

1. 输入形状或形状推导用的输入值没有设置完整；`inferShapes` 可帮助定位。
2. 输出长度依赖输入数据内容，例如筛选非零元素。即使输入尺寸固定，输出长度也可能到执行时才知道。

第 2 类通常需要 `IOutputAllocator`，或根据 `getMaxOutputSize` 等接口设计安全的上界分配策略，本节示例不支持。**不能“先 enqueue 再分配输出”**：执行前必须给输出提供足够的地址，或注册输出分配器。[来源 S2]

## 第 4 步：计算字节数，分配四块缓冲区

对于本节限定的 FP32、线性布局：

```text
元素数 = 各维度相乘
字节数 = 元素数 × sizeof(float)

[1,3,640,640] → 1,228,800 个元素 → 4,915,200 字节
[1,84,8400]   →   705,600 个元素 → 2,822,400 字节
```

不能把负维度转成 `size_t` 后再乘，它会变成巨大正数。完整示例的计算函数会拒绝未解析维度、空张量并检查乘法溢出；空张量并非 TensorRT 一概不支持，而是本教学程序的限制。

```cpp
void* d_in = nullptr;
void* d_out = nullptr;
void* h_in = nullptr;
void* h_out = nullptr;

CUDA_CHECK(cudaMalloc(&d_in, in_bytes));
CUDA_CHECK(cudaMalloc(&d_out, out_bytes));
CUDA_CHECK(cudaMallocHost(&h_in, in_bytes));
CUDA_CHECK(cudaMallocHost(&h_out, out_bytes));
```

`CUDA_CHECK` 在完整示例中定义：检查 CUDA 返回值并报告错误。各 API 的作用与释放方式：

| 缓冲区 | 分配 API | 用途 | 释放 API |
|---|---|---|---|
| `d_in` | `cudaMalloc` | GPU 读取的输入 | `cudaFree` |
| `d_out` | `cudaMalloc` | GPU 写入的输出 | `cudaFree` |
| `h_in` | `cudaMallocHost` | CPU 填充、H2D 传输的页锁定输入 | `cudaFreeHost` |
| `h_out` | `cudaMallocHost` | D2H 传输、CPU 读取的页锁定输出 | `cudaFreeHost` |

**为什么两端主机缓冲区都用页锁定内存？** 普通 `std::vector<float>` / `malloc` 内存一般可被操作系统换页；页锁定内存不能被换出，便于 GPU DMA 传输。对于 CPU↔GPU 异步拷贝，应使用页锁定主机内存，才能获得文档所描述的异步传输行为与重叠机会。[来源 S3、S4]

但不要把规则简化成“函数名带 Async 就绝不阻塞”或“普通内存每次一定完全同步”。CUDA 文档说明，具体行为取决于参数与传输方向，普通主机内存可能需要暂存并导致同步，API 也可能因资源原因阻塞。页锁定内存也不是无限资源，应在初始化时分配、重复使用，而不是每帧大量申请。

## 第 5 步：准备输入，再按名字绑定显存地址

为了先验证管线，本节把每个输入元素填成 `0.5f`：

```cpp
std::fill_n(static_cast<float*>(h_in), in_elements, 0.5f);

if (!context->setTensorAddress(input_name, d_in) ||
    !context->setTensorAddress(output_name, d_out))
    throw std::runtime_error("绑定张量地址失败");
```

注意两个不同动作：

- **填充/拷贝数据**改变内存中的内容。
- **绑定地址**只是告诉 Context “名字为 images 的张量从这个地址读”，不会自动把 `h_in` 拷贝到 `d_in`，也不会替你申请内存。

对 `kDEVICE` I/O 绑定的是 `d_in` / `d_out`，不是主机地址。直接使用 `cudaMalloc` 返回的地址可满足本例的设备地址对齐需求；从大块内存中切出子缓冲区时，还要遵守 `setTensorAddress` 的对齐要求。[来源 S2]

替换成真实图片时，应按模型要求准备 resize/letterbox、通道顺序、归一化、NCHW 排列和 batch。`0.5f` 是管线测试数据，不是有效检测输入，也不能用于评估模型精度。

## 第 6 步：在同一条非默认 stream 上排队并等待

```cpp
cudaStream_t stream{};
CUDA_CHECK(cudaStreamCreateWithFlags(&stream, cudaStreamNonBlocking));

CUDA_CHECK(cudaMemcpyAsync(d_in, h_in, in_bytes,
                          cudaMemcpyHostToDevice, stream));
if (!context->enqueueV3(stream))
    throw std::runtime_error("enqueueV3 失败");
CUDA_CHECK(cudaMemcpyAsync(h_out, d_out, out_bytes,
                          cudaMemcpyDeviceToHost, stream));
CUDA_CHECK(cudaStreamSynchronize(stream));
// 现在才能读取 h_out。
```

这是独立展示的执行片段；动态模型应像完整示例那样，在选择 profile 前就创建 stream。

同一条 stream 的顺序保证：

```text
GPU 队列：H2D 完成 → 推理完成 → D2H 完成
CPU：     提交工作 ───────────→ Synchronize 等待 ──→ 读取 h_out
```

逐行理解：

1. `cudaMemcpyAsync(...HostToDevice...)` 提交输入拷贝；返回不代表 GPU 已完成。
2. `enqueueV3` 提交推理；返回 `true` 说明提交成功，不证明 GPU 已经算完或结果正确。
3. `cudaMemcpyAsync(...DeviceToHost...)` 在同一队列上等待推理后回传结果。
4. `cudaStreamSynchronize` 等待这条 stream 的工作完成，也可能暴露之前异步工作产生的 CUDA 错误。

`cudaStreamNonBlocking` 是 stream 与 legacy 默认 stream 之间的同步选项，不表示 `cudaStreamSynchronize` 不会阻塞 CPU。不要使用默认 stream（传 `0`）作为本例的推理 stream：TensorRT 10.10 的 `enqueueV3` 文档警告，这可能因额外 `cudaDeviceSynchronize()` 造成性能问题。[来源 S2、S5]

**异步提交 ≠ 本例已有流水线重叠。** 本例只有一组缓冲区，并在每次推理末尾等待；它是容易验证的基线。多帧重叠、双缓冲和多 Context 属于 [3.3](3.3-sync-async-parallel.md)。

等待完成之前，不得覆盖 `h_in`、复用/释放 `d_in` 和 `d_out`，也不得读取 `h_out`。本节保守地等所有步骤完成后才复用资源。

## 完整示例：保存为 `run_infer.cpp`

这个程序直接读取 3.1 生成的 `.engine`，**不接收 ONNX，也不自动构建 Engine**。它包含 Logger、文件读取、错误检查和资源回收，不依赖未定义的 `loadOrBuild()`。

为突出执行顺序，使用一个小型 RAII 资源类。正常路径显式同步并检查错误；异常路径在析构中尽力同步，然后释放资源。析构不能抛异常。

```cpp
#include <NvInfer.h>
#include <cuda_runtime_api.h>

#include <algorithm>
#include <cmath>
#include <fstream>
#include <iostream>
#include <limits>
#include <memory>
#include <stdexcept>
#include <string>
#include <vector>

class Logger final : public nvinfer1::ILogger {
public:
    void log(Severity severity, const char* message) noexcept override {
        if (severity <= Severity::kWARNING)
            std::cerr << "[TRT] " << message << '\n';
    }
};

void checkCuda(cudaError_t status, const char* call) {
    if (status != cudaSuccess)
        throw std::runtime_error(std::string(call) + ": " + cudaGetErrorString(status));
}
#define CUDA_CHECK(call) checkCuda((call), #call)

std::vector<char> readEngine(const std::string& path) {
    std::ifstream file(path, std::ios::binary | std::ios::ate);
    if (!file) throw std::runtime_error("无法打开 Engine: " + path);
    auto end = file.tellg();
    if (end <= 0) throw std::runtime_error("Engine 为空或无法获取长度");
    const auto length = static_cast<std::streamoff>(end);
    if (static_cast<unsigned long long>(length) >
        std::numeric_limits<size_t>::max() ||
        length > std::numeric_limits<std::streamsize>::max())
        throw std::runtime_error("Engine 文件过大");
    std::vector<char> bytes(static_cast<size_t>(length));
    file.seekg(0);
    if (!file.read(bytes.data(), static_cast<std::streamsize>(length)))
        throw std::runtime_error("Engine 读取不完整");
    return bytes;
}

std::string shapeString(const nvinfer1::Dims& dims) {
    std::string text = "[";
    for (int i = 0; i < dims.nbDims; ++i) {
        if (i) text += ",";
        text += std::to_string(dims.d[i]);
    }
    return text + "]";
}

size_t elements(const nvinfer1::Dims& dims) {
    if (dims.nbDims < 0) throw std::runtime_error("无效形状");
    size_t count = 1; // rank 0 的标量有一个元素。
    for (int i = 0; i < dims.nbDims; ++i) {
        if (dims.d[i] <= 0)
            throw std::runtime_error("未解析维度或本例不支持的空张量: " + shapeString(dims));
        const auto dim = static_cast<size_t>(dims.d[i]);
        if (count > std::numeric_limits<size_t>::max() / dim)
            throw std::runtime_error("元素数溢出");
        count *= dim;
    }
    return count;
}

size_t floatBytes(size_t count) {
    if (count > std::numeric_limits<size_t>::max() / sizeof(float))
        throw std::runtime_error("字节数溢出");
    return count * sizeof(float);
}

struct CudaResources {
    cudaStream_t stream{};
    void* d_in = nullptr;
    void* d_out = nullptr;
    void* h_in = nullptr;
    void* h_out = nullptr;

    CudaResources() = default;
    CudaResources(const CudaResources&) = delete;
    CudaResources& operator=(const CudaResources&) = delete;
    ~CudaResources() noexcept {
        if (stream) cudaStreamSynchronize(stream);
        if (d_in) cudaFree(d_in);
        if (d_out) cudaFree(d_out);
        if (h_in) cudaFreeHost(h_in);
        if (h_out) cudaFreeHost(h_out);
        if (stream) cudaStreamDestroy(stream);
    }
};

int main(int argc, char** argv) {
    if (argc < 2) {
        std::cerr << "用法: " << argv[0] << " model.engine [输入各维度，如 1 3 640 640]\n";
        return 1;
    }
    try {
        Logger logger;
        auto data = readEngine(argv[1]);
        auto runtime = std::unique_ptr<nvinfer1::IRuntime>(
            nvinfer1::createInferRuntime(logger));
        if (!runtime) throw std::runtime_error("创建 Runtime 失败");
        auto engine = std::unique_ptr<nvinfer1::ICudaEngine>(
            runtime->deserializeCudaEngine(data.data(), data.size()));
        if (!engine) throw std::runtime_error("反序列化 Engine 失败");
        auto context = std::unique_ptr<nvinfer1::IExecutionContext>(
            engine->createExecutionContext());
        if (!context) throw std::runtime_error("创建 Context 失败");

        const char* input = nullptr;
        const char* output = nullptr;
        int inputs = 0, outputs = 0;
        for (int i = 0; i < engine->getNbIOTensors(); ++i) {
            const char* name = engine->getIOTensorName(i);
            const auto mode = engine->getTensorIOMode(name);
            std::cout << name << " "
                      << (mode == nvinfer1::TensorIOMode::kINPUT ? "INPUT" : "OUTPUT")
                      << " engine=" << shapeString(engine->getTensorShape(name))
                      << " dtype=" << static_cast<int>(engine->getTensorDataType(name))
                      << " format=" << engine->getTensorFormatDesc(name)
                      << " location=" << static_cast<int>(engine->getTensorLocation(name))
                      << '\n';
            if (engine->getTensorDataType(name) != nvinfer1::DataType::kFLOAT ||
                engine->getTensorFormat(name) != nvinfer1::TensorFormat::kLINEAR ||
                engine->getTensorLocation(name) != nvinfer1::TensorLocation::kDEVICE ||
                engine->isShapeInferenceIO(name))
                throw std::runtime_error("本例只支持 FP32/LINEAR/DEVICE 且非形状推导 I/O: "
                                         + std::string(name));
            if (mode == nvinfer1::TensorIOMode::kINPUT) {
                input = name;
                ++inputs;
            } else if (mode == nvinfer1::TensorIOMode::kOUTPUT) {
                output = name;
                ++outputs;
            }
        }
        if (inputs != 1 || outputs != 1)
            throw std::runtime_error("本例需要恰好一个输入和一个输出");

        // 声明在 context 后面，异常时先等待 GPU，再销毁 context。
        CudaResources buffers;
        CUDA_CHECK(cudaStreamCreateWithFlags(&buffers.stream, cudaStreamNonBlocking));
        auto actual = engine->getTensorShape(input);
        bool dynamic = false;
        for (int i = 0; i < actual.nbDims; ++i)
            dynamic = dynamic || actual.d[i] == -1;

        if (dynamic) {
            if (argc != 2 + actual.nbDims)
                throw std::runtime_error("动态输入需要传入全部维度（包括静态维度）");
            if (!context->setOptimizationProfileAsync(0, buffers.stream))
                throw std::runtime_error("选择 profile 0 失败");
            for (int i = 0; i < actual.nbDims; ++i) {
                const std::string text = argv[i + 2];
                size_t used = 0;
                const long long value = std::stoll(text, &used);
                if (used != text.size() || value <= 0 ||
                    value > std::numeric_limits<int32_t>::max())
                    throw std::runtime_error("维度必须是有效正整数");
                actual.d[i] = static_cast<int32_t>(value);
            }
            if (!context->setInputShape(input, actual))
                throw std::runtime_error("设置输入形状失败：检查静态维度及 profile 0 范围");
        } else if (argc != 2) {
            throw std::runtime_error("静态 Engine 不需要传入维度");
        }
        if (context->inferShapes(0, nullptr) != 0)
            throw std::runtime_error("形状推导失败或输入信息不完整");
        const auto in_dims = context->getTensorShape(input);
        const auto out_dims = context->getTensorShape(output);
        const size_t in_elements = elements(in_dims);
        const size_t out_elements = elements(out_dims);
        const size_t in_bytes = floatBytes(in_elements);
        const size_t out_bytes = floatBytes(out_elements);
        std::cout << "输入: " << input << " " << shapeString(in_dims)
                  << " " << in_bytes << " 字节\n";
        std::cout << "输出: " << output << " " << shapeString(out_dims)
                  << " " << out_bytes << " 字节\n";

        CUDA_CHECK(cudaMalloc(&buffers.d_in, in_bytes));
        CUDA_CHECK(cudaMalloc(&buffers.d_out, out_bytes));
        CUDA_CHECK(cudaMallocHost(&buffers.h_in, in_bytes));
        CUDA_CHECK(cudaMallocHost(&buffers.h_out, out_bytes));
        std::fill_n(static_cast<float*>(buffers.h_in), in_elements, 0.5f);
        if (!context->setTensorAddress(input, buffers.d_in) ||
            !context->setTensorAddress(output, buffers.d_out))
            throw std::runtime_error("绑定张量地址失败");

        CUDA_CHECK(cudaMemcpyAsync(buffers.d_in, buffers.h_in, in_bytes,
                                  cudaMemcpyHostToDevice, buffers.stream));
        if (!context->enqueueV3(buffers.stream))
            throw std::runtime_error("enqueueV3 失败");
        CUDA_CHECK(cudaMemcpyAsync(buffers.h_out, buffers.d_out, out_bytes,
                                  cudaMemcpyDeviceToHost, buffers.stream));
        CUDA_CHECK(cudaStreamSynchronize(buffers.stream));

        const auto* result = static_cast<const float*>(buffers.h_out);
        size_t nonfinite = 0;
        for (size_t i = 0; i < out_elements; ++i)
            if (!std::isfinite(result[i])) ++nonfinite;
        std::cout << "输出前 " << std::min<size_t>(5, out_elements) << " 个值: ";
        for (size_t i = 0; i < std::min<size_t>(5, out_elements); ++i)
            std::cout << result[i] << ' ';
        std::cout << "\n非有限值数量: " << nonfinite << '\n';
        // 对本例的普通浮点模型，将非有限值视为需要排查的异常。
        return nonfinite == 0 ? 0 : 2;
    } catch (const std::exception& error) {
        std::cerr << "错误: " << error.what() << '\n';
        return 1;
    }
}
```

## 编译与运行：一步一步验证

### 1. 确认安装路径与 Engine

`NvInfer.h` 来自 TensorRT，`cuda_runtime_api.h` 来自 CUDA Toolkit。运行程序只需链接 `nvinfer` 和 `cudart`；不解析 ONNX，因此这里不需要链接 `nvonnxparser`。

以下路径是本课程机器的安装示例；换机器后先改成自己的路径：

```bash
export TRT_ROOT="$HOME/tensorrt/TensorRT-10.10.0.31"
export CUDA_ROOT="$HOME/cuda-11.8"
ls "$TRT_ROOT/include/NvInfer.h" "$CUDA_ROOT/include/cuda_runtime_api.h"
export LD_LIBRARY_PATH="$TRT_ROOT/lib:$CUDA_ROOT/lib64:${LD_LIBRARY_PATH:-}"
```

### 2. 编译刚保存的文件

```bash
g++ -std=c++17 -O2 -Wall -Wextra run_infer.cpp -o run-infer \
    -I"$TRT_ROOT/include" -I"$CUDA_ROOT/include" \
    -L"$TRT_ROOT/lib" -L"$CUDA_ROOT/lib64" \
    -lnvinfer -lcudart
```

本机已使用上述 TensorRT 10.10.0.31 和 CUDA 11.8 路径编译并链接此示例。`-Wall -Wextra` 可能输出 TensorRT 头文件内部的弃用或未使用参数警告；它们与编译失败不同，应留意真正的 `error:`。

也可将同样的头文件路径与链接库加入 1.2 的 CMake 配置。缺头文件检查 `-I`；`cannot find -lnvinfer` 检查 `-L`；运行时 `libnvinfer.so` 找不到则检查 `LD_LIBRARY_PATH`。若 Engine 使用额外插件，还需要对应插件库、注册或加载步骤，不在本例范围内。

### 3. 先运行静态模型

在课程仓库根目录执行，使用 3.1 已构建的文件：

```bash
./run-infer homework/tensorrt/model/model.engine
```

如果你的 Engine 保存在其他位置，就替换路径；不能把 `.onnx` 当成 `.engine` 传入。现有 Engine 若不兼容当前环境，应在当前环境按 3.1 重建。

对于另行构建、profile 0 允许 `[1,3,640,640]` 的动态 Engine：

```bash
./run-infer dynamic.engine 1 3 640 640
```

此命令不意味着仓库中的静态模型会自动变成动态模型。

### 4. 核对输出，不要照抄期望数值

本机使用仓库当前的 `model.engine` 和常量 `0.5f` 输入，实际运行得到：

```text
images INPUT engine=[1,3,480,640] dtype=0 format=Row major linear FP32 format (kLINEAR) location=0
output0 OUTPUT engine=[1,21,6300] dtype=0 format=Row major linear FP32 format (kLINEAR) location=0
输入: images [1,3,480,640] 3686400 字节
输出: output0 [1,21,6300] 529200 字节
输出前 5 个值: 1.49012e-07 0 0 0 0
非有限值数量: 0
```

核对计算：`1×3×480×640×4 = 3,686,400`，`1×21×6300×4 = 529,200`。TensorRT 10.10 的 `dtype=0` 对应 `kFLOAT`，`location=0` 对应 `kDEVICE`（`1` 才是 `kHOST`）。[来源 S1、S6]

这是一份实际运行记录，不是所有模型的标准答案。重新构建、修改模型或换硬件后，数值可能不同；换模型后名字和尺寸也可能不同。示例前五个值多数为零，仍然完成了执行链路。

验证分三层：

- **元信息正确**：I/O 数量、名字、类型、布局、实际形状符合模型约定；字节数计算正确。
- **执行管线跑通**：所有 API 成功，最终同步成功，CPU 能读取回传输出。对本例普通模型，非有限值数量应为 0。
- **模型结果正确**：使用真实预处理数据，与 ONNX Runtime 等参考实现比较，再验证后处理与业务指标。这一层不由常量输入测试证明。

全零输出不必然是程序错误，有些模型和输入确实会产生零；有限值也不必然意味着正确。不能用“前五个数不是零”替代模型验证。

## 常见问题：按失败的步骤排查

| 现象 | 优先检查 | 处理方向 |
|---|---|---|
| Engine 反序列化失败 | 文件是否完整、是否误传 ONNX、版本/GPU 是否兼容、插件是否可用 | 查看 Logger，按 3.1 在目标环境重建 |
| 本例提示不支持 I/O 类型或格式 | 实际 Engine 元信息 | FP16 要用半精度数据与正确字节数；向量化格式要处理填充，不能删掉检查硬跑 |
| `setInputShape` 返回 false | 是否选对 profile，rank/静态维度是否匹配，动态维度是否在范围内 | 核对构建时 MIN/OPT/MAX，传入真实输入尺寸 |
| `inferShapes` 非 0 | 动态尺寸是否全部设置，是否存在未绑定的形状推导 I/O | 获取缺失张量名并补充输入；本例拒绝形状推导 I/O |
| 输出维度仍有 `-1` | 是遗漏形状信息，还是数据依赖输出 | 后者实现输出分配器或安全上界策略，不要先执行再补缓冲区 |
| `cudaMalloc` / `cudaMallocHost` 失败 | 打印出的字节数、可用显存、页锁定资源 | 排除负维度/溢出，再考虑降低 batch 或复用缓冲区 |
| `enqueueV3` 返回 false | 每个 I/O 是否都有有效地址，类型、形状、profile 是否匹配 | 同时查看 TensorRT Logger，不能继续把输出当作有效结果 |
| 最终同步报错 / 非法访问 | 拷贝大小、缓冲区容量、资源是否提前释放、插件实现 | 异步错误可能延迟出现；用 Compute Sanitizer 定位 |
| 输出异常但 API 都成功 | 数据布局、通道顺序、归一化、I/O 类型、真实输入与参考结果 | 常量测试只验证管线；回到 2.2 和 Module 4 核对预处理/后处理 |
| 吞吐不高 | 默认 stream、每帧分配、每帧立即等待、是否真有多帧重叠 | 本例是基线，后续在 3.3 学习事件与缓冲区复用 |

安装了 CUDA Compute Sanitizer 时，可对同一程序检查 GPU 内存访问：

```bash
"$CUDA_ROOT/bin/compute-sanitizer" --tool memcheck \
    ./run-infer homework/tensorrt/model/model.engine
```

## 来源与阅读顺序

为了区分“API 的规定”和“本节为了便于学习选择的实现”，下面列出具体来源及要查的内容。TensorRT 依据 NVIDIA 官方仓库的 `release/10.10` 头文件注释；CUDA 在线文档会更新，应通过 Archive 选择与本机 Toolkit 对应的版本。

1. **S1 — [TensorRT 10.10：NvInferRuntime.h](https://github.com/NVIDIA/TensorRT/blob/release/10.10/include/NvInferRuntime.h)**。搜索 `ICudaEngine`、`createExecutionContext`、`getTensorShape`、`getTensorDataType`、`getTensorFormat`、`getTensorLocation`：核对 Engine 元信息、Context 创建和内存管理策略。
2. **S2 — [同一头文件中的 IExecutionContext](https://github.com/NVIDIA/TensorRT/blob/release/10.10/include/NvInferRuntime.h)**。按 `setOptimizationProfileAsync → setInputShape → inferShapes → getTensorShape → setTensorAddress → enqueueV3` 顺序读注释。重点核对 profile 选择顺序、输出地址/分配器、地址对齐、异步生命周期和默认 stream 警告；数据依赖输出另查 `IOutputAllocator`、`getMaxOutputSize`。
3. **S3 — [CUDA Runtime API：Memory Management](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__MEMORY.html)**。搜索 `cudaMalloc`、`cudaMallocHost`、`cudaMemcpyAsync`、`cudaFreeHost`：核对内存位置、分配/释放配对和拷贝参数。
4. **S4 — [CUDA Runtime API：API Synchronization Behavior](https://docs.nvidia.com/cuda/cuda-runtime-api/api-sync-behavior.html)**。先读 `Memcpy` 的 `Asynchronous` 部分，尤其是 pageable host memory 暂存与可能同步的说明，再理解为什么本例把输入和输出都放在页锁定主机内存。
5. **S5 — [CUDA Runtime API：Stream Management](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__STREAM.html)**。搜索 `cudaStreamCreateWithFlags`、`cudaStreamNonBlocking`、`cudaStreamSynchronize`：核对创建选项、与默认 stream 的关系以及等待范围。
6. **S6 — [TensorRT 10.10：NvInferRuntimeBase.h](https://github.com/NVIDIA/TensorRT/blob/release/10.10/include/NvInferRuntimeBase.h)**。搜索 `DataType` 核对数据类型与元素大小；位置枚举 `TensorLocation` 定义在 S1 的 `NvInferRuntime.h` 中。

**本节的教学选择**：只支持一进一出 FP32/LINEAR/DEVICE、只使用 profile 0、用常量输入、在末尾立即同步。这些不是 TensorRT 的通用限制，而是为了先建立一个尺寸正确、顺序明确、可检查错误的基线。

## 自检与 What's Next

能回答下面四个问题，才算理解了本节，而不只是复制代码：

1. `h_in` 与 `d_in` 有什么区别？为什么绑定 `d_in` 后还要 H2D？
2. 动态输入设置后，为什么用 Context 而不是 Engine 的输出形状算字节数？
3. `enqueueV3` 返回后，能否马上读 `h_out`？哪一步保证读取安全？
4. 如果 I/O 是 `kHALF`，为什么不能继续用 `float*` 和 `sizeof(float)`？

你已经完成：加载 Engine → 创建 Context → 确定实际形状 → 分配缓冲区 → 绑定地址 → H2D → 推理 → D2H → 等待并读取。下一节 [3.3 同步、异步与并行](3.3-sync-async-parallel.md) 将从这个基线出发，讨论怎样在资源不被提前覆盖的前提下持续处理多帧。
