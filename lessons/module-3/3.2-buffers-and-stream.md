# 3.2 分配缓冲区，在 CUDA 流上执行推理

> **对应 SLT**：我能分配输入输出显存与页锁定内存，并在 CUDA 流上执行推理。
> **课时类型**：Developer Documentation
> **版本**：TensorRT 10.10.0.31（API 已核对）
> **前置**：3.1 构建并缓存 engine

---

## engine 只是计划，context 才会执行

`ICudaEngine` 描述「网络怎么算」，但它自己不能跑。要执行，得从 engine 创建一个 **`IExecutionContext`**。一个 engine 可以创建多个 context，它们共享权重，各自持有自己的执行状态。

执行一次推理需要四样东西：

1. 一个 **execution context**
2. **输入缓冲区**（显存）
3. **输出缓冲区**（显存）
4. 一条 **CUDA stream**（执行队列）

这条链的每一步都要和「名字」对应上：TensorRT 10 里，输入输出张量是按**名字**绑定的。

---

## 先取得名字与尺寸

从 engine 里把 IO 张量的名字、形状读出来，这是后面所有分配与绑定的依据：

```cpp
const char* input_name  = nullptr;
const char* output_name = nullptr;

for (int i = 0; i < engine->getNbIOTensors(); ++i) {
    const char* name = engine->getIOTensorName(i);
    if (engine->getTensorIOMode(name) == nvinfer1::TensorIOMode::kINPUT)
        input_name = name;
    else
        output_name = name;
}
```

算张量元素个数（各维相乘）：

```cpp
size_t volume(const nvinfer1::Dims& d)
{
    size_t v = 1;
    for (int i = 0; i < d.nbDims; ++i) v *= static_cast<size_t>(d.d[i]);
    return v;
}
```

**动态 shape 要补全**。如果模型某些维是 `-1`，得在绑定前用 `setInputShape` 给出确定值：

```cpp
auto in_dims = engine->getTensorShape(input_name);
for (int i = 0; i < in_dims.nbDims; ++i)
    if (in_dims.d[i] < 0)
        in_dims.d[i] = 1;   // 例如 batch 维固定为 1；按你的模型改

if (!context->setInputShape(input_name, in_dims)) {
    std::cerr << "设置输入形状失败\n";
    return 1;
}
```

静态 shape 的模型没有 `-1`，这一步即使调用也无害。

---

## 分配三类内存

```cpp
const size_t in_bytes  = volume(in_dims) * sizeof(float);
const size_t out_bytes = volume(engine->getTensorShape(output_name)) * sizeof(float);

void* d_in  = nullptr;   // 显存：输入
void* d_out = nullptr;   // 显存：输出
float* h_out = nullptr;  // 主机：输出（页锁定）

cudaMalloc(&d_in,  in_bytes);
cudaMalloc(&d_out, out_bytes);
cudaMallocHost(&h_out, out_bytes);   // 页锁定内存，异步 D2H 才有效
```

三类内存各司其职：

| 内存 | 分配方式 | 位置 | 用途 |
|---|---|---|---|
| `d_in` / `d_out` | `cudaMalloc` | 显存 | TensorRT 读写 |
| `h_out` | `cudaMallocHost` | 主机（页锁定） | 结果回传，异步高效 |
| 输入主机数据 | 由你提供 | 主机 | 预处理后的 NCHW float |

**为什么输出用页锁定内存**：只有页锁定内存才能让 `cudaMemcpyAsync` 真正异步。用普通 `malloc` 会退化成同步拷贝，Module 2.3 算过这笔账。

---

## 绑定与执行

把显存地址绑定到张量名，然后入队执行：

```cpp
context->setTensorAddress(input_name,  d_in);
context->setTensorAddress(output_name, d_out);

cudaStream_t stream;
cudaStreamCreate(&stream);

// h_in 是预处理好的 NCHW float 数据
cudaMemcpyAsync(d_in, h_in, in_bytes, cudaMemcpyHostToDevice, stream);  // H2D
context->enqueueV3(stream);                                            // 推理
cudaMemcpyAsync(h_out, d_out, out_bytes, cudaMemcpyDeviceToHost, stream); // D2H
cudaStreamSynchronize(stream);                                         // 等待完成
```

三步都排在同一条 stream 上，天然按序执行。`cudaStreamSynchronize` 之后，`h_out` 就是结果。

> **官方警告**：`enqueueV3` 不要用默认 stream（传 `0`）。TensorRT 会为它在默认 stream 上插入额外的 `cudaDeviceSynchronize()`，把异步变回同步，性能明显下降。**永远显式创建一条非默认 stream。**

## 完整示例

```cpp
#include <NvInfer.h>

#include <cuda_runtime_api.h>

#include <fstream>
#include <iostream>
#include <memory>
#include <vector>

size_t volume(const nvinfer1::Dims& d)
{
    size_t v = 1;
    for (int i = 0; i < d.nbDims; ++i) v *= static_cast<size_t>(d.d[i]);
    return v;
}

int main(int argc, char** argv)
{
    Logger logger;   // 见 3.1

    std::vector<char> engine_data = loadOrBuild(argv[1], logger);   // 见 3.1

    auto runtime = std::unique_ptr<nvinfer1::IRuntime>(
        nvinfer1::createInferRuntime(logger));
    auto engine = std::unique_ptr<nvinfer1::ICudaEngine>(
        runtime->deserializeCudaEngine(engine_data.data(), engine_data.size()));
    if (!engine) return 1;

    auto context = std::unique_ptr<nvinfer1::IExecutionContext>(
        engine->createExecutionContext());

    const char* input_name = nullptr;
    const char* output_name = nullptr;
    for (int i = 0; i < engine->getNbIOTensors(); ++i) {
        const char* name = engine->getIOTensorName(i);
        if (engine->getTensorIOMode(name) == nvinfer1::TensorIOMode::kINPUT)
            input_name = name;
        else
            output_name = name;
    }

    auto in_dims = engine->getTensorShape(input_name);
    for (int i = 0; i < in_dims.nbDims; ++i)
        if (in_dims.d[i] < 0) in_dims.d[i] = 1;
    context->setInputShape(input_name, in_dims);

    const size_t in_bytes  = volume(in_dims) * sizeof(float);
    const size_t out_bytes = volume(engine->getTensorShape(output_name)) * sizeof(float);

    void* d_in = nullptr;
    void* d_out = nullptr;
    float* h_out = nullptr;
    std::vector<float> h_in(volume(in_dims), 0.5f);   // 占位输入，实际用预处理结果

    cudaMalloc(&d_in, in_bytes);
    cudaMalloc(&d_out, out_bytes);
    cudaMallocHost(&h_out, out_bytes);

    context->setTensorAddress(input_name, d_in);
    context->setTensorAddress(output_name, d_out);

    cudaStream_t stream;
    cudaStreamCreate(&stream);

    cudaMemcpyAsync(d_in, h_in.data(), in_bytes, cudaMemcpyHostToDevice, stream);
    context->enqueueV3(stream);
    cudaMemcpyAsync(h_out, d_out, out_bytes, cudaMemcpyDeviceToHost, stream);
    cudaStreamSynchronize(stream);

    std::cout << "输入: " << input_name << "  " << in_bytes << " 字节\n";
    std::cout << "输出: " << output_name << "  " << out_bytes << " 字节\n";
    std::cout << "输出前 5 个值: ";
    for (int i = 0; i < 5; ++i) std::cout << h_out[i] << " ";
    std::cout << "\n";

    cudaFree(d_in);
    cudaFree(d_out);
    cudaFreeHost(h_out);
    cudaStreamDestroy(stream);
    return 0;
}
```

## 验证

```bash
./run-infer model.onnx
```

预期输出：

```
输入: images  4915200 字节
输出: output0  2822400 字节
输出前 5 个值: 0.0123 0.0456 ...
```

**判断标准**：
- 字节数 = 元素数 × 4（float32）。例如 `[1,3,640,640]` 输入是 `1×3×640×640×4 = 4,915,200` 字节；`[1,84,8400]` 输出是 `1×84×8400×4 = 2,822,400` 字节。
- 输出前几个值是有限浮点数，不是 `nan` 或一堆 0。

要让结果有意义，把 `h_in` 换成**真实预处理后的数据**（见 2.2 与 Module 4）。本节的目的是把执行链路跑通，不是验证模型精度。

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `setInputShape` 返回 false | 形状超出优化 profile 范围 | 检查模型的 profile 允许范围 |
| `enqueueV3` 返回 false | 有张量未绑定，或形状冲突 | 确认每个 IO 张量都 `setTensorAddress` |
| 结果全是 0 / nan | 输入数据未填或形状不符 | 检查 `h_in` 的尺寸与通道顺序 |
| 输出字节数算错 | 输出 shape 含 `-1` | 先 `enqueueV3` 再查输出形状，或按模型固定值 |
| 速度慢 | 用了默认 stream | 显式 `cudaStreamCreate` |
| 显存泄漏 | 忘记 `cudaFree` / `cudaFreeHost` | 用 RAII 包装，或成对释放 |
