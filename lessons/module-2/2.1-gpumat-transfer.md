# 2.1 GpuMat 与主机↔设备数据搬运

> **对应 SLT**：我能用 GpuMat 在主机与设备间上传和下载图像数据。
> **课时类型**：Developer Documentation
> **前置**：OpenCV（CPU 版）基本用法、能读一张图

---

## 为什么数据要「搬」

CPU 能看到的内存（主机内存）和 GPU 能看到的内存（显存）是两块独立的空间。GPU 的算子只能读写显存，CPU 读不到显存里的像素。所以想让 GPU 处理一张图，第一步永远是**把图从主机内存搬到显存**；处理完再**搬回来**给 CPU 用。

OpenCV CUDA 用 `cv::cuda::GpuMat` 表示「显存里的一块图像」。它和 `cv::Mat` 的关系，可以理解成：

| | `cv::Mat` | `cv::cuda::GpuMat` |
|---|---|---|
| 数据位置 | 主机内存 | 显存 |
| 谁来读写 | CPU | GPU 算子 / CUDA kernel |
| CPU 能否直接访问像素 | 能 | **不能**（必须先 `download`） |

`GpuMat` 的接口刻意做得和 `Mat` 很像（都有 `rows`、`cols`、`type()`），但你**不能**拿 `gpu_mat.ptr()` 在 CPU 侧读像素，那段地址对 CPU 无效。

---

## 上传与下载

两个动作，方向相反：

```cpp
#include <opencv2/core.hpp>
#include <opencv2/core/cuda.hpp>

cv::Mat host = cv::imread("frame.jpg");     // 主机内存里的 BGR 图
if (host.empty()) return -1;

cv::cuda::GpuMat device;
device.upload(host);                         // H2D：主机 → 显存

// ... 这里可以用 cv::cuda:: 的算子处理 device ...

cv::Mat result;
device.download(result);                     // D2H：显存 → 主机
```

- `upload(host)`：把主机内存的像素拷到显存。
- `download(host)`：把显存像素拷回主机内存。

方向记法：**upload 是「往上送」，送到 GPU**；download 是「往下取」，取回 CPU。

---

## 一个容易忽略的事实：GpuMat 不会自动同步

OpenCV CUDA 的算子相对主机是**异步**的。`upload` 返回时，数据**可能还没真正传到显存**——它只是被排进了队列。

在 CPU 侧立刻用 `host` 没问题（`upload` 不会改 `host`），但如果你用**流（stream）**做异步下载，就要自己保证「下载完成」再读结果：

```cpp
cv::cuda::Stream stream;
device.download(result, stream);   // 异步下载，立即返回
stream.waitForCompletion();        // 必须等待，否则 result 可能是空的或半旧数据
```

不带 stream 的 `download(host)` 是**同步**的，返回时结果一定就绪。初学阶段先用同步版本，确认流程跑通，再引入流。

## 完整可运行示例

```cpp
#include <opencv2/core.hpp>
#include <opencv2/core/cuda.hpp>
#include <opencv2/imgcodecs.hpp>

#include <chrono>
#include <iostream>

int main()
{
    if (cv::cuda::getCudaEnabledDeviceCount() <= 0) {
        std::cerr << "没有可用的 CUDA 设备\n";
        return 1;
    }
    cv::cuda::printShortCudaDeviceInfo(cv::cuda::getDevice());

    cv::Mat host = cv::imread("frame.jpg");
    if (host.empty()) {
        std::cerr << "读图失败\n";
        return 1;
    }

    cv::cuda::GpuMat device;

    auto t0 = std::chrono::high_resolution_clock::now();
    device.upload(host);
    auto t1 = std::chrono::high_resolution_clock::now();

    cv::Mat back;
    device.download(back);
    auto t2 = std::chrono::high_resolution_clock::now();

    auto ms = [](auto a, auto b) {
        return std::chrono::duration<double, std::milli>(b - a).count();
    };

    std::cout << "原图尺寸: " << host.cols << "x" << host.rows
              << " 通道: " << host.channels() << "\n";
    std::cout << "显存尺寸: " << device.cols << "x" << device.rows
              << " 通道: " << device.channels() << "\n";
    std::cout << "上传(H2D): " << ms(t0, t1) << " ms\n";
    std::cout << "下载(D2H): " << ms(t1, t2) << " ms\n";
    std::cout << "往返一致: " << (cv::countNonZero(host.reshape(1) != back.reshape(1)) == 0
                                   ? "是" : "否") << "\n";
    return 0;
}
```

编译时记得让 CMake 找到带 CUDA 的 OpenCV（见 Module 1）。

---

## 验证要点

这段程序**每步都有可见输出**，不要让它静默跑完：

1. **设备信息**：`printShortCudaDeviceInfo` 应打印出 GPU 名称与算力。
2. **尺寸一致**：显存尺寸应与原图一致（`1920x1080`、3 通道）。
3. **往返一致**：上传再下载后，像素应与原图完全相同（差异像素数为 0）。
4. **耗时可见**：H2D 与 D2H 各打印一个毫秒数，这正是 Module 2.3 要分析的「往返成本」。

**预期**：往返一致应为「是」。若为「否」，先检查是否用了异步 `download` 而忘了等待。

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 段错误 / 非法访问 | 用 `gpu_mat.ptr()` 在 CPU 侧读像素 | 显存指针只能给 CUDA 用，读像素前先 `download` |
| 下载后图是空的 | 异步下载未等待 | `stream.waitForCompletion()` 或改用同步 `download` |
| `getCudaEnabledDeviceCount()==0` | 链接了不带 CUDA 的 OpenCV | 用带 CUDA 的 OpenCV 构建，并设置好运行库路径 |
| 尺寸对但像素不对 | 通道顺序或类型不符 | 确认输入是 `CV_8UC3`，BGR 顺序 |
| 第一次调用特别慢 | CUDA 上下文与显存首次初始化 | 预热一次再计时 |
