# 2.2 在 GPU 上做预处理：缩放与 letterbox padding

> **对应 SLT**：我能用 cv::cuda 的缩放与 padding 算子在 GPU 上完成预处理。
> **课时类型**：Developer Documentation
> **前置**：2.1 GpuMat 与主机↔设备数据搬运

---

## 预处理在做什么

检测模型通常只吃**固定尺寸**的输入，比如 640×640。但摄像头给出的图是任意尺寸，比如 1920×1080。中间这段「把任意图变成模型输入」的活，就是预处理。

最常见的一种叫 **letterbox**：先按比例缩放，让长边贴合目标尺寸，再把短边用灰色 padding 补齐。这样做的目的是**不改变物体比例**。如果直接拉伸成 640×640，物体形状会变形，检测精度会掉。

```text
原图 1920x1080                  letterbox 到 640x640
┌──────────────────┐            ┌──────────────┐
│                  │            │▓▓▓▓▓▓▓▓▓▓▓▓▓▓│  ← 灰色 padding (124,124,124)
│                  │   ──→      │              │
│                  │            │   缩放后的图  │
└──────────────────┘            │              │
                                │▓▓▓▓▓▓▓▓▓▓▓▓▓▓│
                                └──────────────┘
```

预处理还有一步常见的：把 BGR 转成 RGB、把像素值除以 255 归一化、把 HWC 排布转成 NCHW。本节先做**缩放 + padding**，通道与归一化放到 Module 4 的融合 kernel 里一次做完。

---

## 两个 GPU 算子

OpenCV CUDA 把这两个操作都做成了显存内的算子：

```cpp
#include <opencv2/cudawarping.hpp>   // resize, copyMakeBorder

cv::cuda::GpuMat src, resized, padded;

// 按比例缩放到 (new_w, new_h)
cv::cuda::resize(src, resized, cv::Size(new_w, new_h),
                 0, 0, cv::INTER_LINEAR);

// 四周补边到 (target_w, target_h)，填充灰色 124
cv::cuda::copyMakeBorder(resized, padded,
                         pad_y, target_h - new_h - pad_y,
                         pad_x, target_w - new_w - pad_x,
                         cv::BORDER_CONSTANT, cv::Scalar(124, 124, 124));
```

每个算子最后一个参数都可以传一个 `cv::cuda::Stream`，让整条链在同一个流上按序执行，省掉中间的同步。先不带流，确认结果正确，再加流优化。

---

## letterbox 的尺寸怎么算

缩放比取「宽高缩放比里较小的那个」，保证缩放后仍能塞进目标框：

```cpp
const float scale = std::min(static_cast<float>(target_w) / src.cols,
                             static_cast<float>(target_h) / src.rows);
const int new_w = std::min(target_w, (int)std::round(src.cols * scale));
const int new_h = std::min(target_h, (int)std::round(src.rows * scale));
const int pad_x = (target_w - new_w) / 2;
const int pad_y = (target_h - new_h) / 2;
```

`pad_x` / `pad_y` 后面**会用到**：后处理把检测框从 640×640 坐标映射回原图时，必须减掉 padding 再除以 scale。所以算出来要留着，不能丢。

## 完整可运行示例

```cpp
#include <opencv2/core.hpp>
#include <opencv2/core/cuda.hpp>
#include <opencv2/imgproc.hpp>     // CPU 对照
#include <opencv2/cudawarping.hpp>
#include <opencv2/imgcodecs.hpp>

#include <algorithm>
#include <cmath>
#include <iostream>

int main()
{
    cv::Mat host = cv::imread("frame.jpg");
    if (host.empty()) return 1;

    const int target_w = 640, target_h = 640;
    const float scale = std::min((float)target_w / host.cols,
                                 (float)target_h / host.rows);
    const int new_w = std::min(target_w, (int)std::round(host.cols * scale));
    const int new_h = std::min(target_h, (int)std::round(host.rows * scale));
    const int pad_x = (target_w - new_w) / 2;
    const int pad_y = (target_h - new_h) / 2;

    // ---- GPU 路径 ----
    cv::cuda::GpuMat g_src, g_resized, g_padded;
    g_src.upload(host);
    cv::cuda::resize(g_src, g_resized, cv::Size(new_w, new_h), 0, 0, cv::INTER_LINEAR);
    cv::cuda::copyMakeBorder(g_resized, g_padded,
                             pad_y, target_h - new_h - pad_y,
                             pad_x, target_w - new_w - pad_x,
                             cv::BORDER_CONSTANT, cv::Scalar(124, 124, 124));
    cv::Mat gpu_out;
    g_padded.download(gpu_out);

    // ---- CPU 对照 ----
    cv::Mat cpu_resized, cpu_out;
    cv::resize(host, cpu_resized, cv::Size(new_w, new_h), 0, 0, cv::INTER_LINEAR);
    cv::copyMakeBorder(cpu_resized, cpu_out,
                       pad_y, target_h - new_h - pad_y,
                       pad_x, target_w - new_w - pad_x,
                       cv::BORDER_CONSTANT, cv::Scalar(124, 124, 124));

    std::cout << "缩放后: " << new_w << "x" << new_h
              << "  pad: " << pad_x << "," << pad_y << "\n";
    std::cout << "GPU 输出: " << gpu_out.cols << "x" << gpu_out.rows << "\n";

    cv::Mat diff;
    cv::absdiff(gpu_out, cpu_out, diff);
    double max_val = 0;
    cv::minMaxLoc(diff.reshape(1), nullptr, &max_val);
    std::cout << "GPU 与 CPU 最大像素差: " << max_val << "\n";
    return 0;
}
```

---

## 验证要点

1. **输出尺寸**：应为 `640x640`。
2. **padding 位置**：上下或左右应有灰色边，比例与 `pad_x`/`pad_y` 一致。
3. **与 CPU 一致**：GPU 与 CPU 的最大像素差应很小（同用 `INTER_LINEAR` 时通常为 0 或个位数）。
4. **记住 pad 与 scale**：把它们打印出来，后处理阶段要用。

**预期**：`最大像素差` 接近 0。若明显偏大，检查 `resize` 的目标尺寸是否传成了 `640x640` 而不是 `new_w×new_h`（这一步错了，比例就变形了）。

---

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 图被拉伸变形 | resize 直接给了目标尺寸 | 先算 `new_w/new_h`，再 padding |
| 输出尺寸不对 | padding 参数计算错 | 用 `(target - new) / 2` 分配两侧 |
| padding 颜色不是灰 | `Scalar` 通道顺序或数值错 | 用 `Scalar(124,124,124)` |
| GPU 与 CPU 差很多 | 插值方式不同 / 忘了 padding | 两边用同一 `INTER_LINEAR` |
| 速度没比 CPU 快 | 只有一张图，往返开销盖过收益 | 看 2.3；GPU 优势要在批量或流水线里体现 |
