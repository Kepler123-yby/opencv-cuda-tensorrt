# 2.3 往返的代价：为什么 GPU 预处理不总是更快

> **对应 SLT**：我能解释 host↔device 往返如何成为 GPU 预处理的性能瓶颈。
> **课时类型**：Exploration
> **前置**：2.1、2.2

---

## 一个反直觉的现象

把预处理搬到 GPU 上，直觉上应该更快。但很多人在真实项目里第一次这么做完，发现**帧率没涨，甚至略降**。

原因不在于 GPU 算得慢，而在于**数据在 PCIe 上往返的次数变多了**。这一节把账算清楚：一次推理的端到端时间到底被谁占着。

---

## 三段耗时，两种带宽

GPU 处理一帧，时间花在三段：

```text
[主机内存] --H2D--> [显存] --compute--> [显存] --D2H--> [主机内存]
            ↑                                    ↑
        走 PCIe 总线                          走 PCIe 总线
```

关键事实：**显存带宽和 PCIe 带宽差了一个数量级。**

| 通道 | 典型带宽 | 谁在用 |
|---|---|---|
| GPU 显存（GDDR6） | 300–1000 GB/s | GPU 算子、kernel |
| PCIe 3.0 x16（H2D/D2H） | 实测约 12 GB/s | 上传、下载 |
| PCIe 4.0 x16 | 实测约 24 GB/s | 上传、下载 |

在 GPU 内部搬数据飞快，一旦要跨到主机，速度就掉到几十分之一。

---

## 算一笔账

一张 1920×1080 的 BGR 图，数据量：

```text
1920 × 1080 × 3 字节 ≈ 6.22 MB
```

上传 + 下载的往返：

```text
6.22 MB × 2 ≈ 12.44 MB
```

按 PCIe 3.0 实测 12 GB/s：

```text
12.44 MB / 12 GB/s ≈ 1.04 ms
```

也就是**光是把一帧搬一个来回，就要约 1 毫秒**，还没算任何计算。而一个精简的检测模型在 GPU 上推理，可能就是 1–3 毫秒。于是搬数据的开销，已经能占到端到端时间的相当一部分。

更糟的是：如果预处理在 GPU 上做完却又**下载回主机**，后处理再**上传回显存**，那一帧就要走**两个来回**，约 2 毫秒。Module 4 的零拷贝要消灭的正是这多出来的一个来回。

---

## 页锁定内存为什么更快

同样是主机内存，分配方式不同，传输速度也不同：

- **可分页内存（pageable）**：`new` / `malloc` 出来的。驱动不能直接对它做 DMA，得先拷进一块临时页锁定缓冲，再传到显存。等于多了一道内部中转，带宽更低。
- **页锁定内存（pinned / page-locked）**：`cudaMallocHost` 分配的。物理页固定，驱动可直接 DMA，带宽拉满，`cudaMemcpyAsync` 才能真正异步。

所以「我用了 `cudaMemcpyAsync` 但没变快」多半是因为源/目标是普通内存。异步的前提是页锁定。

---

## 什么时候 GPU 预处理真的划算

不是「GPU 一定更快」，而是要看这几个条件：

- **往返次数**：每多一个 H2D/D2H，就多一次约 0.5–1 毫秒的固定成本。
- **计算密度**：预处理本身很轻（一次 resize），GPU 的优势有限；等到预处理 + 推理 + 后处理都在 GPU 上、且**中间结果不落地**，收益才明显。
- **批量**：一次搬一大块数据（batch），比一帧一帧搬，单位数据的传输成本低得多。
- **流水线**：让「搬第 N+1 帧」和「算第 N 帧」重叠，能进一步把传输时间藏起来（Module 3 的多路并行）。

一句话：**GPU 加速的对手从来不是 CPU 算子，而是 PCIe 往返。**

---

## 一些想请你思考的问题

- 你的流水线里，一帧数据被搬了几个来回？能不能减少其中任意一个？
- 如果 resize 只花 0.1 毫秒，而往返要 1 毫秒，把 resize 放 GPU 图什么？
- 你的内存是 `malloc` 还是 `cudaMallocHost`？如果是前者，`cudaMemcpyAsync` 真的异步了吗？
- 当模型推理只要 1 毫秒、而往返要 2 毫秒时，端到端时间主要由谁决定？
